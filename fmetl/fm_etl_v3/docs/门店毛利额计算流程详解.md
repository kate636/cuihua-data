# 门店毛利额计算流程详解（v4.0）

> 本文档详细梳理 v4 门店毛利额计算流程，包括 BOM 拆分机制、所有 cost 相关指标定义、涉及的字段和底表。

## 二、cost 相关指标定义对照表

> ⚠️ 这是最容易混淆的部分，共 **8 个 cost 相关字段**，来源不同、口径不同。

| 字段名 | 所在表 | 来源 | 粒度 | 定义 | 适用场景 |
|-------|-------|------|------|------|---------|
| **cost_price** | atomic_cost_price | `strategy_fm_inventory_pool_di` | SKU | 门店库存成本价（标品/非拆分商品的财务成本） | 标品、非日清商品 |
| **avg_inbound_price** | atomic_inventory | `strategy_fm_purchase_di` | SKU | 根 parent 入库均价（元/kg）= 根parent入库额/入库量 | BOM parent 的进货均价 |
| **sale_article_price** | atomic_receive_sale | `strategy_fm_receive_sale_di` | sub | sub 分摊单价 = split_sale_article_amt / sale_article_qty | 上游已分摊好的 BOM 结果 |
| **purchase_price** | atomic_receive_sale | 同上 | parent | 根 parent 入库均价 = inbound_amount / inbound_qty | 同 avg_inbound_price |
| **bom_unit_cost** | t_calc_sku_cost | 计算 | sub | BOM 分摊后的 sub 单位成本（多 parent 加权） | BOM sub SKU |
| **effective_unit_cost** | t_calc_sku_cost | 计算（四级fallback） | SKU | **★ 最终使用的有效单位成本** | 所有 SKU 的统一成本口径 |
| **sub_unit_cost** | t_calc_bom_alloc | 计算 | parent×sub | 单次分摊的单位成本 | BOM 分摊溯源 |
| **outstock_cost_price** | t_atomic_wide | atomic_scm | SKU | 供应链出库成本价（含税） | 供应链毛利计算 |

### effective_unit_cost 四级 fallback 详细说明

```sql
effective_unit_cost = COALESCE(
    NULLIF(cost_price, 0),       -- ① DIRECT: 标品成本价
    NULLIF(bom_unit_cost, 0),    -- ② BOM_ALLOC: BOM分摊后sub成本
    NULLIF(avg_inbound_price, 0),-- ③ PURCHASE_AVG: 进货均价兜底
    0                            -- ④ MISSING: 告警
)

cost_source = CASE
    WHEN NULLIF(cost_price, 0) IS NOT NULL      THEN 'DIRECT'
    WHEN NULLIF(bom_unit_cost, 0) IS NOT NULL   THEN 'BOM_ALLOC'
    WHEN NULLIF(avg_inbound_price, 0) IS NOT NULL THEN 'PURCHASE_AVG'
    ELSE 'MISSING'
END
```

**cost_source 分布（2026-04-20 滨江宏岸店）**：

| cost_source | SKU数 | 平均成本 | 含义 |
|------------|------|---------|------|
| **DIRECT** | 763 | 11.34 | 标品，有 cost_price |
| **BOM_ALLOC** | 83 | 26.77 | BOM拆分sub，多parent加权 |
| **PURCHASE_AVG** | 5 | 7.36 | 自采标品，无cost_price用进货均价 |
| **MISSING** | 919 | 0.00 | 无任何成本数据（生鲜常缺失） |

## 三、BOM 拆分机制详解

### 3.1 数据来源三级 fallback

| 优先级 | 来源 | 字段 | 说明 |
|-------|------|------|------|
| **1** | RECEIVE_SALE | `atomic_receive_sale.sale_article_qty` | 上游商分库已拆好的 BOM 事实，最权威 |
| **2** | COMPOSE | `compose_out_qty × dressing_rate` | 有加工转出记录时，用 BOM 出肉率估算 |
| **3** | BOM_THEORETICAL | `receive_qty × dressing_rate` | 无事实，纯理论估算 |

### 3.2 cost_rate 三级 fallback

| 优先级 | 来源 | 说明 |
|-------|------|------|
| **1** | ORIGINAL | `atomic_bom_relation.cost_rate`（BOM 配置的成本比例） |
| **2** | INFERRED_BY_PRICE | 用 `sub.original_price × dressing_rate` 权重归一化反推 |
| **3** | EQUAL_WEIGHT | 平均分配给所有 sub |

### 3.3 多 parent 加权公式

当 sub 来自多个 parent（如"排骨"从"白条猪"和"优鲜猪"都拆出来）：

```sql
bom_unit_cost = Σ(parent_inbound_qty × dressing_rate × parent_unit_price)
              / Σ(parent_inbound_qty × dressing_rate)

-- 等价于：按"分摊进货量占比"加权 parent 均价
```

## 四、门店毛利额双口径对比

### 4.1 销售方程（推荐使用）

```
store_profit_sales = sale_amt
                    - sale_qty × effective_unit_cost
                    - know_lost_amt
                    - unknow_lost_amt
```

**优点**：
- 直接使用 SKU 的 `effective_unit_cost`，BOM 拆分后更准确
- 不依赖 `compose_in/out` 和库存方程
- 对标 `strategy_fm_allowance_di.profit_amt`（官方销售方程）

### 4.2 库存方程（观测用）

```
store_profit_stock = sale_amt
                    - (receive_amt + compose_in_amt - compose_out_amt)
                    + (end_stock_amt - init_stock_amt)
                    - know_lost_amt - unknow_lost_amt
```

**问题**：
- 依赖 `compose_in/out` 数据（加工转换数据质量不稳定）
- 依赖库存方程推算的期末库存（负库存时异常）
- **当前数据问题**：滨江宏岸店 `store_profit_stock = -2,090`，差异巨大

### 4.3 差异定位

```
store_profit_diff = store_profit_sales - store_profit_stock
```

用于定位"哪张单据漏了"：
- `diff > 0` → 库存方程漏了进货/加工入
- `diff < 0` → 库存方程多算了损耗/加工出

## 五、关键底表说明

### 5.1 strategy_fm_purchase_di（官方 BOM 分摊表）

这是 **v4 最关键的数据源改进**。商分库已经做了 BOM 分拆：

| 字段 | 含义 |
|------|------|
| `sale_article_id` | sub SKU（如排骨） |
| `sale_article_qty` | sub 分摊数量 |
| `sale_article_purchase_amt` | ★ sub 分摊进货额（官方预分摊） |
| `avg_inbound_price` | 根 parent 入库均价 |

**v3 vs v4 差异**：
- v3：只用 `sale_article_qty`，金额自己算
- v4：同时用 `sale_article_purchase_amt` 作为 `receive_amt` 主口径

### 5.2 strategy_fm_receive_sale_di（BOM 拆分事实）

| 字段 | 含义 |
|------|------|
| `article_id` | 根 parent（如优鲜大白猪A级） |
| `sale_article_id` | sub SKU（如优鲜排骨） |
| `inbound_qty/amount` | parent 当天入库量/额 |
| `sale_article_qty` | sub 从本 parent 分摊的 qty |
| `split_sale_article_amt` | ★ sub 从本 parent 分摊的金额 |
| `sale_article_price` | sub 分摊单价 |

### 5.3 strategy_fm_inventory_pool_di（成本价池）

只有 **标品/非拆分商品** 有 cost_price：
- 生鲜 BOM sub（排骨/五花）**没有** cost_price，必须走 BOM_ALLOC
- 标品（饮料/零食）**有** cost_price，走 DIRECT

## 六、当前数据问题诊断

### 6.1 MISSING 成本占比高（919 SKU = 52%）

这些 SKU 无任何成本数据，毛利计算结果为：
- `sale_amt - sale_qty × 0 - losses = sale_amt - losses`
- 毛利率 ≈ 100%（虚高）

**原因**：生鲜商品在 `inventory_pool` 里没有成本价记录。

### 6.2 库存方程异常（-2,090 vs -264）

**诊断**：
```sql
-- 查 compose_in/out 数据
SELECT SUM(compose_in_amt), SUM(compose_out_amt)
FROM t_calc_amounts WHERE business_date = '2026-04-20';

-- 查库存方程分量
SELECT 
    SUM(init_stock_amt), SUM(receive_amt), 
    SUM(compose_in_amt), SUM(compose_out_amt),
    SUM(end_stock_amt), SUM(know_lost_amt)
FROM t_calc_amounts;
```

**可能原因**：
- `compose_in_amt > compose_out_amt` 大量加工转入但未转出
- `end_stock_amt - init_stock_amt` 库存增加过多
- 数据质量问题

## 七、与 StarRocks 基准差异分析

| 指标 | v4 销售方程 | StarRocks 基准 | 差异原因 |
|------|------------|---------------|---------|
| 门店毛利额 | -264.61 | -344.04 | v4 用 BOM_ALLOC 成本（26.77），基准可能用其他口径 |
| 全链路毛利 | 298.36 | 260.60 | 供应链毛利计算口径差异 |
| 烘焙类毛利 | -143.39 | -611.80 | **差异最大 468**，烘焙 BOM 成本取值差异 |
| 熟食类毛利 | -539.09 | -39.57 | **差异 -500**，熟食加工成本取值差异 |

**关键差异**：StarRocks 基准可能用原始 `cost_price` 或 `avg_inbound_price`，
v4 用 `effective_unit_cost`（四级 fallback），BOM sub SKU 成本更准确。

## 八、建议改进方向

1. **降低 MISSING 比例**
   - 补充 `strategy_fm_inventory_pool_di` 生鲜 SKU 成本价
   - 或用 `strategy_fm_receive_sale.sale_article_price` 兜底

2. **修复库存方程**
   - 检查 `atomic_compose` 数据质量
   - 确认 `compose_in/out` 是否匹配

3. **统一口径对标**
   - 与商分团队确认 `strategy_fm_levels_result` 的成本取值路径
   - 决定使用销售方程还是库存方程作为官方口径
