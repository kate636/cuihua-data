## 3. 单一最大可修复问题: BOM 父品利润不为零

### 根因

BOM 父品 (如优鲜排骨 20003470) 在 FM 中产生了巨大的非零利润:
- QDM: +2,299 (QDM 把利润算在父品上 → 子品利润为负)
- FM: −638 (FM 把亏损算在父品上 → 子品利润也不对)

**BOM 父品不应该产生独立利润**。父品只有进货和 BOM 拆分，不对外销售。其利润公式应为 0：
```
profit = sale(0) − receive − bom_in(0) + bom_out − compose_in + compose_out
       + end_stock − init_stock
       = −receive + bom_out + end_stock − init_stock
```

当 `sale=0, bom_in=0` 时，如果 `end_stock` 没有正确清零，利润就会偏离 0。

### 影响范围

| 品类 | 受影响 SKU | 差异额 |
|------|:---:|------|
| 猪肉类 | 10+ | ~±7,000 (相抵后 −40) |
| 水产类 | 2-3 | ~±500 |
| 牛羊类 | 2-3 | ~±400 |
| 禽类 | 2-3 | ~±250 |
| 预制菜 | 2-3 | ~±300 |

**修正 BOM 父品利润为零后**，这些扭曲将大幅减少。子品利润会相应调整。

### 修复位置

`fmetl/calculated/profit.py` — BOM 父品识别 + 利润强制归零:

```python
# 当前 profit.py 未对 BOM 父品做特殊处理
# 需要: 识别 BOM 父品 (t_calc_bom_alloc 中作为 parent 的 SKU)
# → profit 强制设为 0
# → 差值通过 stock_transfer_out 转移到子品的 stock_transfer_in
```

`profit.py` 中的 `stock_transfer_out` 逻辑 (来自 `stock.py`) 已经将父品剩余库存按 BOM 比例转移给子品，但可能没有正确触发。需要排查:

1. `stock_transfer_out` 的计算是否正确
2. 转移后父品的 `end_stock` 是否归零
3. 转移金额是否在毛利公式中正确反映

### 预期效果

- 猪肉类差异 ±7,000 → ~±500 (品类级从 −40 可能改善至 ±100 内)
- 水产/牛羊/禽类大幅改善
- 总毛利差异预期从 +19.0% 降至 +10-12%
