## 一、核心结论（TL;DR）

1. **困扰已久的"BOM 对称残差 349.35"不是 bug，是定义口径问题**（把握 95%）。它精确等于 `Σstock_transfer_in_amt`——BOM 父品残余库存转移给子品时，子品 `bom_in` 增加但父品 `bom_out` 按设计不补（FIX-004 已回滚）。`transfer_in == transfer_out == 349.35` 自身守恒。已修正 etl-check 与 CLAUDE.md 的判定口径。
2. **"136 个零成本 SKU"的真实画像**：euc≤0 共 5546 行 / 1155 SKU，但其中 **5410 行无销售（无害）**，只有 **136 行有销售**（销售额 4883 元，约 100% 虚高毛利）。根因是 `cost_price`/`current_price×0.40` 兜底被移除、且 FIX-002/FIX-011 未实现，属**已知结构性缺口**（把握 90%）。
3. **BOM 分摊全局守恒**：`Σbom_alloc_amt = 18183.48 = Σbom_out_amt`，分摊→bom_out 一一对应，共享组多父品（含 50 个 3+ 父品链）**未造成全局超分**（把握 90%）。
4. **父品库存转移机制正确**：转移后 `end_stock>0` 的父品行 = **0**，父品 profit≈0（把握 95%）。
5. **毛利公式 + FIX-019 自洽**（把握 90%）：6/18–22 总毛利差 +18.9% → +6.3%。

#### 附带发现：库存方程平衡检查 #5 同样被钉零分支"污染"（把握 95%）

健康检查 #5（`init+inflows-outflows-end-unknow ≈ 0`）实测残差 **-812.52**，并非 ≈0。逐层拆解：

| 切片 | 残差 | 说明 |
|------|:---:|------|
| dc='0'（软日清） | +32.77 | 设计内偏离（软日清不强制清存量） |
| dc='1' 钉零行（end≈0 & unknow>0 & eq<0） | **-897.29** | = `Σ(2×eq_end_qty)` **精确吻合** |
| dc='1' 非钉零纯净行 | +52.0 | 浮点 + 少量边角 |

钉零分支 `end=0, unknow=-eq`（eq<0）使恒等式 `end+unknow` 应等于 eq（负）却得到 `-eq`（正），每行偏离 `2×eq`。这是 **FIX-019 的会计镜像**：FM 把超卖/超损钉零并记为正的 unknow_lost，而物理平衡要求的是负 unknow（=盘盈/init 被低估）。QDM 允许负 end 而 FM 钉零——这是两者库存口径的根本差异。

> **🟡 待用户决策（与 FIX-019 同源，不在本轮动）**：钉零分支把超卖记为"额外未知损耗"（正 unknow）还是应识别为"init 被低估"（负 unknow / 盘盈）？前者高估损耗、后者承认数据不可知。FIX-019 已在**利润侧**做了选择（扣回透支成本）；**库存数量侧**的对称选择尚未做，影响库存方程平衡口径，但不影响利润（利润已由 FIX-019 处理）。把握 95% 认为"这是口径选择而非 bug"。本轮仅修正健康检查的判定公式，未改钉零语义。
