## 二、已解决的问题

### 2.1 加工关系（compose）成本计算

**问题**：compose_in_amt（成品入库金额）依赖QDM源表值，源表部分成品金额明显偏低（如现烤老婆饼62个仅1.58元）。

**方案**：改为配方推算，不再使用QDM源表值。

- 成品 `compose_in_amt = compose_in_qty × Σ(raw_qty / yield_qty × raw_base_euc)`
- 原料 `compose_out_amt = compose_out_qty × base_euc`（价值守恒）
- 成本通过 `EUC → end_stock → 次日init_stock` 跨日链式传递

**当前状态**：✅ 已实现，本地缓存22条活跃加工关系（`data/processing_relations.json`），远程DB同步。

### 3.2 烘焙日清品清单补充（P1 — 需业务持续维护）

**现状**：FM将**全部烘焙类SKU**标记为 `day_clear='1'`（非日清），未售品作为end_stock（库存资产）结转。QDM将烘焙品按日清处理，未售品记为损耗。

**数据**：烘焙类24天累计：
- FM end_stock从4,556涨至14,236（+9,680），日均+403

烘焙类**不在白名单中**，因此全部按dim_day_clear的自然标签（均为'1'，非日清）。

**业务判断**：烘焙品确有保质期（1-3天），非严格日清。但QDM按日清处理是出于损益保守原则。需业务确认：

**待办**：

### 3.3 库存金额算法确认细节（P1 — 需对齐QDM口径）

**当前FM算法**：加权平均含期初库存（v10 EUC）

```
euc = (init_stock_amt + self_receive_amt + compose_net_amt + bom_alloc_amt)
    / (init_stock_qty + self_receive_qty + compose_net_qty + bom_alloc_qty)
```

**验证结论**：数据证明5月全月所有SKU的 `init_stock单价 ≈ receive单价`（无>0.5元差异的案例），加权平均EU算法本身**没有产生库存重估效应**。

**实际利润驱动路径**：

```
进货(receive) → 库存资产(end_stock↑) → 销售时才转COGS(sale_cost)
                 ↓
           end_stock - init_stock > 0 → 利润公式中 + (end-init)
```

当 `receive > sale` 时（进货大于销售），库存积累，FM账面利润增加。这是正常的存货会计处理，不是计算bug。

**需业务确认的点**：

| 事项 | FM当前做法 | 需确认 |
|------|-----------|--------|
| EUC兜底链 | cost_price → avg_inbound_price → ffill → current_price×0.40 | 40%成本率假设是否合理？ |
| 日清品EUC | 与非日清品统一公式（加权平均） | 日清品是否应用不同成本法？ |
| 零成本SKU | 5月有1,054个SKU的EUC=0（占比~5%） | 这些SKU的利润计算是否正确？ |
| compose_in_amt兜底 | 无加工关系时保留QDM源表值 | 是否应用avg_inbound_price兜底？ |

**待办**：
- [ ] 与QDM侧确认成本计算方法（cost_price vs 加权平均 vs 移动平均）
- [ ] 确认40%成本率假设（`current_price × 0.40`）是否适用于所有品类
- [ ] 排查零成本SKU（1,054个），确认是否需要强制兜底

### 3.4 FM不产生负损耗（盘盈）的问题（P2 — 结构性差异）

**现状**：QDM的损耗（lost_amt）可以是大额负数（盘盈/inventory gain），直接增加利润。FM的库存方程残差（unknow_lost）理论上可以为负（允许盘盈），但实际很少出现。

**QDM盘盈典型案例**（5月）：

| 日期 | 分类 | QDM损耗 | 说明 |
|------|------|---------|------|
| 5/21 | 冷藏加工类 | **-642** | 大额盘盈，直接增加当日利润 |
| 5/13 | 冷藏加工类 | **-106** | 盘盈 |
| 5/08 | 烘焙类 | **-361** | 盘盈 |
| 5/21 | 烘焙类 | **-588** | 盘盈 |

**FM的unknow_lost机制**：

当前库存方程中，`unknow_lost = eq - end`（正常分支下为0）。FM已在v10 fix中允许unknow_lost为负值（盘盈），但实际触发条件有限：

```
1. is_counted (人工盘点): unknow = eq - actual → 可为负（actual > eq时=盘盈）
2. day_clear='0' (软日清): unknow = 新供给 - sale - klost → 可为负
3. eq < 0 (负库存保护): unknow = -eq → 始终为正
4. 正常: unknow = 0 → 始终为0
```

**根因**：FM和QDM对"损耗"的语义定义根本不同：
- QDM损耗 = 净库存调整（运营记录，正=损耗，负=盘盈）
- FM损耗 = know_lost（源表已知损耗）+ unknow_lost（方程残差）

FM的"正常"分支不产生残差（unknow=0），因此不会出现QDM那种大额盘盈。

**影响分类**：
- 标品类：QDM盘盈~100/天，FM无盘盈 → FM利润偏低~100/天
- 乳制品及水饮类：QDM盘盈~50/天，FM无盘盈 → FM利润偏低~50/天
- 冷藏加工类：QDM盘盈/损耗大幅波动 → FM利润波动小但系统性偏低

**待办**：
- [ ] 确认是否需要引入盘盈机制（如调用 `atomic_inventory_detail` 的实盘数据）
- [ ] 或接受结构性差异（FM偏保守，QDM偏激进）
- [ ] 评估是否在标品类/乳制品类引入定期盘点修正
