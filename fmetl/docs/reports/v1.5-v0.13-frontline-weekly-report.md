# 花家市集门店流程&产品&ETL迭代

## 一、背景

花家市集在熟食联动、炒菜机报损和盘点过程中，现有门店操作依赖人工判断、手工换算和集中补录，容易出现漏录、错录、重复录入和跨日问题。需要同步调整门店流程、产品和 ETL。

改造原则：删除不必要的门店操作；必须保留的操作尽量简化；关系识别、数量换算、校验和兜底由产品与 ETL 承接。

## 二、已知问题与改造方案

| 类别 | 问题 | 怎么改 | 承接方 |
|---|---|---|---|
|  |
| 加工流程 | 烘焙由多人手写记录，再由一人汇总录入，容易漏录、错录或跨日。 | 取消门店加工量填报，统一按采购确认的加工关系由 ETL 自动换算。 | ETL |
| 加工流程 | 采购已在经营平台维护加工关系，门店到货日仍需再次录入 PSD。 | 加工关系只保留经营平台一个入口；采购确认关系、比例和生效日期，门店不再重复录入。 | 采购、产品 |
| 盘点与报损 | 炒菜机报损依赖拍照、表格和事后补录。 | PDA 改为即时报损 | 产品、门店 |
| 盘点与报损 | PDA 加载慢，晚间集中处理容易漏录、重复提交或跨日。 | 支持条码预加载、离线暂存和幂等提交。 | 产品 |
| 盘点与报损 | 盘点可能出现小数点错位；部分入口只能填整数或不能小于 1。 | 支持小数和实际业务单位；提交前校验数量级，差异超过 30% 时提醒。 | 产品 |
| 盘点与报损 | 同一批实物可能同时按验收码和销售码盘点。 | 系统明确唯一盘点码；存在转换关系时只盘库存承接码，并阻止重复提交。 | 产品、采购、ETL |
| 商品转换与收货 | 部分 SKU 实际发生换码、拆包或加工，但系统没有正式关系或当日转换数量，门店需人工换算。 | 按 BOM、加工、包装／换码分别维护关系；固定全转由业务确认，非固定转换记录当日数量，未知关系进入待确认清单。 | 产品、采购、ETL |
| 商品转换与收货 | 供应商多送未登记时，销售后可能形成负库存。 | ETL 将盘盈按负损耗或库存收益处理，不让错误库存跨日。 | ETL |
