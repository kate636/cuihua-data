# FIX-026：发生销售或转出但当天无法计算单位成本时使用备用成本

## 结论

2026-08-06 至 2026-08-11、门店 A3XV 的本地 v0.16 完整重跑中，部分 SKU日期记录发生销售、报损或
内部转出，但期初、收货、销售退回和内部流入均没有形成正的当日用于计算加权单位成本的数量和金额。原逻辑将这些出流按
0 成本计价，同时由 `ISSUE_COST_EVIDENCE` 阻止发布。这会保留前后总额相等，但会系统性高估门店毛利。

本修复只补成本依据，不补库存数量：

1. 优先沿用该 SKU 最近一次有效的正出流成本；
2. 如果从未形成有效成本，使用同门店、同日、同 SKU 的 `inventory_pool.cost_price`；
3. 两者都不存在时继续记为 `MISSING_COST_EVIDENCE`，禁止发布；
4. 只在当日可用用于计算单位成本的数量和金额数量不大于 0 时生效，正常加权成本完全不变；
5. 不把 `inventory_pool` 的库存数量或系统快照写入账本，不人为生成期末库存。

`inventory_pool.cost_price` 在此仍是参考依据，不是主库存来源。该源在本窗口内
`store × date × SKU` 唯一且非负；对 3,521 个已有正成本的可比出流 SKU日期记录，96.85% 的参考成本
与账本成本差异不超过 1%，99.55% 不超过 5%，因此只把它用于最后一层当天没有可用补用已有成本。

## 代码变更

- `mirror/v014_stage.py`：将同日 `inventory_pool.cost_price` 作为 `fallback_cost` 带入标准活动表，
  并校验键唯一、有限、非负。
- `calculations/ledger.py`：按“最近正成本 → 同日参考成本 → 缺依据”确定当天没有可用补用已有成本，写出
  `fallback_cost`、`fallback_cost_source`、`issue_cost_source` 审计列。
- `tests/test_shadow_ledger.py`：覆盖当天没有可用成本负库存强制设为0、参考成本不生成库存、最近正成本优先三个边界。

## 未解决问题

- 严格 ±2% 周门店毛利检查仍有 2 项失败，不能宣称完全对齐。
- 逐日并未都进入 ±5%：08-08 门店毛利高 15.81%，08-06 高 8.61%。
- 熟食仍高 1,832.94 元，缺成本和加工原料不可用集中；蔬菜低 1,190.83 元，盘点角色冲突、
  收货销售码双计和库存/损耗计算规则需要继续拆解。
- 猪肉净差 +630.91 元与关系 SKU 预期差 +640.21 元接近，主要属于显式 BOM/关系计算规则，
  不应为了人为缩小差异 v1.5 直接调账。
- `CATEGORY_SNAPSHOT_EVIDENCE` 仍失败；服务端分类文档写 126 个固定分类 SKU，实际配置为 119 个，
  必须确认历史生效方式后才能发布。
