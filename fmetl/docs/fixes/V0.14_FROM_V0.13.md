# v0.14 相比 v0.13 的实际迭代

> 性质：版本迭代说明，不占用单一 FIX 编号。  
> 对比基线：git `a43d197`（v0.13 weighted shadow ledger）。  
> 当前版本：`fmetl.__version__ = 0.14`。  
> 状态：A3XV 本地七天试算结果已实现；生产差异验收未完成。

## 1. 结论

v0.13 完成了基础结构：整理源业务记录、判断关系类型、计算同日加权成本和库存状态、提供毛利接口，
并能记录不参与计算的问题；但仍缺完整数据接入、整周自动执行、已确认关系记录、内部转换金额计入每日库存和成本、全字段输出和正式发布所需的验证。

v0.14 基于 v0.13 主干建立可实际运行的本地试算过程，独立计算库存、成本、损耗和毛利，
不复用 v1.5 结果。核心变化是将商品关系、事件依据、成本计入每日库存和成本、前一天期末库存转为当天期初库存和输出合同连成
一条可审计链；商品集汇总是新增输出维度之一。

```mermaid
flowchart LR
    A["v0.13\n可验证的初步计算"] --> B["补齐数据来源和统一业务记录"]
    B --> C["按日关系登记"]
    C --> D["正式内部事件"]
    D --> E["连续七日加权账本"]
    E --> F["125 字段七层输出"]
    F --> G["必须通过的检查与 v1.5 只读对比"]
```

## 2. 哪些能力沿用 v0.13

以下能力沿用 v0.13，并在 v0.14 中继续强化：

- SQL 只做抽取、连接和聚合；复杂判断在 Python 完成。
- 销售和退回保留源符号，不全局翻转。
- SKU × 日期稠密网格。
- 外部验收与 BOM、包装、加工内部流分列。
- 同日一次加权成本；下游不重复定价。
- 关系冲突或缺少依据时不计算转换，也不自动使用替代关系、比例或成本。
- 会计毛利与炒菜机／生熟联动展示调整分离。

## 4. 核心计算规则变化

### 4.1 加工从“门店填报”改为“ETL 根据库存变化计算”

v0.13：`compose_di` 实际数量优先，配方仅补缺的一侧。

v0.14：加工关系由采购维护，门店无需填写加工量；正式加工产出为：

```text
成品期末 - 成品期初 - 成品外部验收
+ 成品净销售 + 成品已知报损
+ 其他内部转出 - 其他内部转入
```

缺有效盘点、成品有外部验收、原料不足或关系冲突时，不计算该加工关系。

### 4.2 日清从“库存算法分支”改为“业务标签”

v0.13 的只清当天新增数量并保留期初库存会按新供给、销售和已知损耗计算未知损耗；当业务流程或关系不完整时，差额
容易被归入损耗。

v0.14 取消该分支。只有有效盘点可以产生未知损耗或盘盈；没有有效盘点时按统一库存方程
滚动。`day_clear` 只用于输出分组。

### 4.3 源库存从“可参与覆盖”改为“仅启动和审计”

- `purchase_di.init_stock_*` 只允许作为 D-1 启动种子。
- `purchase_di.end_stock_*` 保留为源观察值，不直接作为正式金额。
- 有效盘点可以覆盖期末数量，但期末金额必须按当日单位成本重算。
- 后续每日期初只能来自上日期末。

### 4.4 商品集从“关系答案”限定为“关系候选”

商品集只说明商品身份接近，不能证明：

- 当天发生了转换；
- 转换方向；
- 转换数量；
- 转换比例。

因此商品集不合并 SKU 用于计算单位成本的数量和金额，也不能替代 BOM、加工或显式换码。

### 4.5 错误不再通过损耗无其他依据时采用

以下错误必须单列：关系缺失、比例缺失、单位缺失、关系冲突、盘点负数、小数点错位、双码
重复盘点、加工原料不足、零成本支出。它们不允许静默进入未知损耗。

### 已验证通过

- 期末数量、期末金额非负。
- SKU 数量与金额方程平衡差为 0。
- 外部销售、退回、验收和已知损耗与标准层一致。
- D+1 期初数量和金额精确继承。
- 内部事件转出金额等于转入金额。
- 正式 BOM 父品期末为 0。

### 尚未通过

- v1.5 差异比较总状态为 `FAIL`。
- 2026-07-28 验收额差异 -76.83 元尚未解释。
- 门店周门店毛利差异约 +3.62%，全链路毛利差异约 +2.81%。
- 多个大分类周毛利差异超过 2%。
- 当前不计入正式计算主要集中在双码重复盘点、缺成本、加工成品缺盘点和商品集缺转换依据。

这些问题不说明账本不前后总额相等，但会阻止 v0.14 作为生产替代版本发布。
