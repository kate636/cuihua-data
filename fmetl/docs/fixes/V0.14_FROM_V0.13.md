# v0.14 相比 v0.13 的实际迭代

> 性质：版本迭代说明，不占用单一 FIX 编号。  
> 对比基线：git `a43d197`（v0.13 weighted shadow ledger）。  
> 当前版本：`fmetl.__version__ = 0.14`。  
> 状态：A3XV 本地七日影子账本已实现；生产差异验收未完成。

## 1. 结论

v0.13 完成了重构主干：事实标准化、关系分型、同日加权成本、库存状态、毛利接口和异常隔离
骨架；但仍缺完整来源接入、整周自动执行、正式关系快照、内部金额过账、全字段输出和发布级
验证。

v0.14 基于 v0.13 主干建立可实际运行的本地影子链路，独立计算库存、成本、损耗和毛利，
不复用 v1.5 结果。核心变化是将商品关系、事件证据、成本过账、库存滚动和输出合同连成
一条可审计链；商品集汇总是新增输出维度之一。

```mermaid
flowchart LR
    A["v0.13\n可验证计算骨架"] --> B["来源与标准层完整化"]
    B --> C["按日关系登记"]
    C --> D["正式内部事件"]
    D --> E["连续七日加权账本"]
    E --> F["125 字段七层输出"]
    F --> G["硬门禁与 v1.5 只读对比"]
```

## 2. 哪些能力沿用 v0.13

以下能力沿用 v0.13，并在 v0.14 中继续强化：

- SQL 只做抽取、连接和聚合；复杂判断在 Python 完成。
- 销售和退回保留源符号，不全局翻转。
- SKU × 日期稠密网格。
- 外部验收与 BOM、包装、加工内部流分列。
- 同日一次加权成本；下游不重复定价。
- 关系冲突或缺证据进入隔离，不静默兜底。
- 会计毛利与炒菜机／生熟联动展示调整分离。

## 4. 核心口径变化

### 4.1 加工从“门店填报”改为“ETL 反推”

v0.13：`compose_di` 实际数量优先，配方仅补缺的一侧。

v0.14：加工关系由采购维护，门店无需填写加工量；正式加工产出为：

```text
成品期末 - 成品期初 - 成品外部验收
+ 成品净销售 + 成品已知报损
+ 其他内部转出 - 其他内部转入
```

缺有效盘点、成品有外部验收、原料不足或关系冲突时不反推，直接隔离。

### 4.2 日清从“库存算法分支”改为“业务标签”

v0.13 的软日清会按新供给、销售和已知损耗计算未知损耗；当业务流程或关系不完整时，差额
容易被归入损耗。

v0.14 取消该分支。只有有效盘点可以产生未知损耗或盘盈；没有有效盘点时按统一库存方程
滚动。`day_clear` 只用于输出分组。

### 4.3 源库存从“可参与覆盖”改为“仅启动和审计”

- `purchase_di.init_stock_*` 只允许作为 D-1 启动种子。
- `purchase_di.end_stock_*` 保留为源观察值，不直接作为正式金额。
- 有效盘点可以覆盖期末数量，但期末金额必须按当日单位成本重算。
- 后续每日期初只能来自上日期末。

### 4.4 商品集从“关系答案”限定为“关系候选”

商品集只说明商品身份接近，不能证明：

- 当天发生了转换；
- 转换方向；
- 转换数量；
- 转换比例。

因此商品集不合并 SKU 成本池，也不能替代 BOM、加工或显式换码。

### 4.5 错误不再通过损耗兜底

以下错误必须单列：关系缺失、比例缺失、单位缺失、关系冲突、盘点负数、小数点错位、双码
重复盘点、加工原料不足、零成本支出。它们不允许静默进入未知损耗。

### 已验证通过

- 期末数量、期末金额非负。
- SKU 数量与金额方程残差为 0。
- 外部销售、退回、验收和已知损耗与标准层一致。
- D+1 期初数量和金额精确继承。
- 内部事件金额守恒。
- 正式 BOM 父品期末为 0。

### 尚未通过

- v1.5 差异比较总状态为 `FAIL`。
- 2026-07-28 验收额差异 -76.83 元尚未解释。
- 门店周门店毛利差异约 +3.62%，全链路毛利差异约 +2.81%。
- 多个大分类周毛利差异超过 2%。
- 当前隔离主要集中在双码重复盘点、缺成本、加工成品缺盘点和商品集缺转换证据。

这些问题不说明账本不守恒，但会阻止 v0.14 作为生产替代版本发布。
