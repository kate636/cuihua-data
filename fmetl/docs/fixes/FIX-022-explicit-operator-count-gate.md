# FIX-022：人工盘点账号依据检查

## 问题

`strategy_fm_store_article_inventory_detail_di` 每个门店、日期、SKU 只有一行。该行可能由人工
账号创建和更新，也可能完全由系统生成。系统快照全部覆盖期末时，无法证明门店完成了实盘，
会把系统库存差异带入未知损耗和次日期初。

## 处理

- `created_by` 或 `updated_by` 为明确人工账号，且 `actual_stock_qty >= 0`：作为正式盘点覆盖期末数量。
- 创建人和更新人均为系统：保留源数量和元数据供审计，`is_counted=false`，期末由库存方程计算。
- 负数盘点、小数点错位和验收码／销售码重复盘点继续不计入正式计算。
- 同日同 SKU 出现多行时直接拒绝标准化，禁止静默选择人工行或系统行。

## 本地验证

- 数据来源：A3XV Hive 源数据副本本地缓存。
- 源数据副本覆盖：2026-07-26 至 2026-08-04。
- 同日同 SKU 重复组：0。
- 正式输出范围：2026-07-27 至 2026-08-04。
- 每日正式人工盘点 SKU：425、466、304、474、564、297、0、423、433。8月2日源表
  2,928条盘点均为系统账号，因此不覆盖期末。
- 负期末库存：0；前一期末与次日期初的数量差、金额差均为 0；8 项每日库存和成本检查全部通过。
- 单元测试：155个通过，0个失败。
