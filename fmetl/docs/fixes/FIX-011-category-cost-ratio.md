## 一、问题定义

### 1.1 背景

FIX-002 计划对 EUC=0 的 SKU 使用 `current_price * 0.40` 作为估算成本。0.40 成本率基于 60% 毛利率假设，但不同品类的实际成本率差异巨大。

### 1.2 为什么 0.40 不够精确

| 品类 | 实际 EUC/Price 比率 | 0.40 假设 | 偏差方向 | 业务影响 |
|------|:---:|:---:|:---:|------|
| 预制菜 (含熟食) | 0.65 | 0.40 | **成本低估 39%** | 利润虚增 |
| 蔬菜类 | 0.72 | 0.40 | **成本低估 45%** | 利润虚增 |
| 冷藏及加工类 (含烘焙) | 0.75 | 0.40 | **成本低估 47%** | 利润虚增 |
| 标品类 | 0.80 | 0.40 | **成本低估 50%** | 利润虚增 |
| 水果类 | 0.85 | 0.40 | **成本低估 53%** | 利润虚增 |

**结论**: 统一使用 0.40 会系统性低估所有品类的成本，导致利润虚增。品类间差异高达 20 个百分点 (0.65 vs 0.85)，差异化成本率可显著提升估算精度。

### 1.3 勘误：CLAUDE.md 中的毛利率假设与实测数据不符

CLAUDE.md 中列出的品类毛利率假设与本次实测数据存在方向性矛盾：

| 品类 | CLAUDE.md 假设 | 实测成本率 | 实测毛利率 | 偏差来源 |
|------|:---:|:---:|:---:|------|
| 烘焙类 | 成本率 ~35% (毛利率 ~65%) | **0.67 (毛利率 ~33%)** | ~33% | 行业基准 vs 小店实际 |
| 标品类 | 成本率 ~65% (毛利率 ~35%) | **0.80 (毛利率 ~20%)** | ~20% | 部分一致 |
| 生鲜类 | 成本率 ~65-75% | **0.72-0.85** | ~15-28% | 方向对, 幅度错 |

**原因分析**: CLAUDE.md 的毛利率假设源自零售行业通用基准，而非 A3XV 门店实际经营数据。本次分析以实测 EUC 数据为准。

## 二、数据验证：从有成本 SKU 反推品类成本率

### 2.1 数据来源与计算方法

- **源表**: `t_calc_stock` (含 `effective_unit_cost`, `sale_qty`, `sale_amt`)
- **价格源**: `atomic_price` (含 `current_price`)
- **分类源**: `dim_goods` (category_level1/2/3)
- **门店**: A3XV (单店)
- **日期范围**: 2026-05-01 至 2026-05-31
- **过滤条件**: `effective_unit_cost > 0`, `sale_qty > 0`
- **聚合方式**: 按 `store_id + business_date + article_id` 合并 day_clear='0' 和 '1'

**关键指标定义**:

```
sale_cost_ratio = SUM(effective_unit_cost * sale_qty) / SUM(sale_amt)
    -- 成本占销售额比例 (含加价因素)

weighted_euc_price_ratio = SUM(effective_unit_cost * sale_qty) / SUM(current_price * sale_qty)
    -- 成本占售价比例 (核心指标：与 FIX-002 的 COST_RATIO 直接对应)
    -- FIX-002 公式: euc = current_price * COST_RATIO
    -- 因此 COST_RATIO 的"正确答案"即为加权 EUC/price 比率
```

## 四、方案设计

### 4.1 推荐：按 L1 大分类设置成本率

**理由**:
1. L1 内部 L2 离散度可接受 (除猪肉类外，标准差 < 0.09)
2. L2 分类过多 (45 个)，维护成本高
3. EUC=0 SKU 分布在 8 个 L1 中，L1 粒度与数据量匹配
4. 实现简单：常量字典，无需 JOIN dim_goods

### 4.2 建议成本率

| L1 大分类 | 加权 EUC/Price | **建议成本率** | 置信度 | 说明 |
|--------|:---:|:---:|:---:|------|
| 预制菜 | 0.65 | **0.66** | 高 | 即食/即热/即烹一致性好 (std=0.015) |
| 蔬菜类 | 0.72 | **0.72** | 高 | L2 集中在 0.69-0.76 |
| 冷藏及加工类 | 0.75 | **0.75** | 中 | 烘焙 0.67 vs 奶制品 0.87，取加权均值 |
| 肉禽蛋类 | 0.77 | **0.77** | 高 | L2 集中在 0.75-0.81 (std=0.025) |
| 水产类 | 0.74 | **0.75** | 中 | L2 集中在 0.77-0.81，虾蟹类拉低至 0.67 |
| 猪肉类 | 0.82 | **0.75** | 低 | 猪分割肉异常 (1.19) 疑似数据问题；使用非异常品类均值 |
| 标品类 | 0.80 | **0.80** | 中高 | L2 集中在 0.75-0.87，取加权均值 |
| 水果类 | 0.85 | **0.85** | 中 | 热带果类 0.90 拉高，但为主要品类 |
| **默认兜底** | — | **0.78** | — | 全局加权均值，用于未匹配分类 |

> 猪肉类 0.75 为去异常后的保守值。猪分割肉类 EUC/price = 1.19 (成本 > 售价)，反映 EUC 计算而非真实成本率问题，不应纳入兜底参考。

### 4.3 是否需要按 L2 细分？

对于以下 L1，内部 L2 差异值得关注，但暂不推荐 L2 粒度兜底：

| L1 | 低端 L2 | 高端 L2 | 差异 | 暂不细分原因 |
|----|:---:|:---:|:---:|------|
| 冷藏及加工类 | 烘焙类 0.67 | 冷藏奶制品 0.87 | 0.20 | 烘焙类只有 69 SKU 有 EUC，覆盖不足 |
| 猪肉类 | 猪骨类 0.63 | 猪分割肉 1.19 | 0.56 | 猪分割肉异常，已通过 L1 保守值规避 |

**后续建议**: 等 EUC 覆盖率提升后 (FIX-001 ~ FIX-010 完成)，重新评估 L2 细分价值。

## 五、实现方案

### 5.1 修改文件

`fmetl/calculated/sku_cost.py`

### 5.2 配置常量

在模块顶部新增常量字典：

```python
# ═══════════════════════════════════════════════════════════════
# 品类差异化成本率 (FIX-011)
# 基于 A3XV 2026年5月有正常EUC的SKU反推
# 算式: euc = current_price * CATEGORY_COST_RATIO[category_level1_description]
# ═══════════════════════════════════════════════════════════════
CATEGORY_COST_RATIO = {
    '预制菜':      0.66,
    '蔬菜类':      0.72,
    '冷藏及加工类': 0.75,
    '水产类':      0.75,
    '猪肉类':      0.75,   # 保守值, 猪分割肉异常排除
    '肉禽蛋类':    0.77,
    '标品类':      0.80,
    '水果类':      0.85,

CATEGORY_COST_RATIO_DEFAULT = 0.78  # 全局加权均值, 未匹配分类的兜底
```

### 5.3 改动详情

在 FIX-002 的 `current_price * 0.40` 兜底层 (V10_RETAIL_ESTIMATED) 中，将硬编码的 `0.40` 替换为品类查找：

```python
# FIX-002 原代码 (待实现):
FALLBACK_COST_RATIO = 0.40
df.loc[fallback_retail, 'effective_unit_cost'] = (
    df.loc[fallback_retail, 'current_price'] * FALLBACK_COST_RATIO
)

# FIX-011 修改后:
# 需要 JOIN dim_goods 获取 category_level1_description
# 或者预先加载分类映射表

# 方案A: 在 sku_cost.py 加载 wide_df 时同时 JOIN dim_goods 的 L1 分类
# 方案B: 使用 category_level1_id (已有) 映射到中文名后查找字典

# 伪代码:
df['cost_ratio'] = df['category_level1_description'].map(
    CATEGORY_COST_RATIO
).fillna(CATEGORY_COST_RATIO_DEFAULT)

df.loc[fallback_retail, 'effective_unit_cost'] = (
    df.loc[fallback_retail, 'current_price'] * df.loc[fallback_retail, 'cost_ratio']
)

```

### 5.4 依赖：需要将 category_level1_description 加载到 sku_cost.py

`sku_cost.py` 当前从 `t_atomic_wide` 取数但不 JOIN `dim_goods`。需要任选以下方案之一：

**方案 A (推荐): 在 SQL 查询中 JOIN dim_goods**

**方案 B: 使用 category_level1_id 数字映射**

`V10_COST_PRICE_FALLBACK` 和 `V10_PROCESSING_RELATION` 不受影响，它们使用实际成本价和配方推算，非比率估算。

       COUNT(DISTINCT sc.article_id) as n_skus,
       AVG(sc.effective_unit_cost / NULLIF(cp.current_price, 0)) as avg_applied_ratio

ORDER BY avg_applied_ratio DESC
