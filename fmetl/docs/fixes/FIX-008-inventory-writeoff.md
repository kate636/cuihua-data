## 一、问题现象

审计报告发现标品类（纸巾/瓶装水/大米/酒）在特定日期出现大额库存核销：

| 日期 | SKU | 名称 | unknow_lost_qty | unknow_lost_amt |
|------|-----|------|:---:|:---:|
| 5/16 | 21311147 | 洁柔纸巾 | 153 | 1,224 |
| 5/16 | 20101541 | 农夫山泉 550ml*12 | 45 | 453 |
| 5/16 | 21306105 | 石湾玉冰烧小酒 | 12 | 167 |
| 5/16 | 21333583 | 奔富葡萄酒 | 1 | 100 |

审计报告认为这些标品**不应该有损耗**。

## 二、数据核查

### 2.1 盘点机制

每日有 ~1,570 SKU 在 `atomic_inventory_detail` 中有 `actual_stock_qty > 0`（`created_by = '系统'` = 系统快照）。stock.py 的 `is_counted` 分支触发：

```
end_stock = actual_stock_qty  (实盘数)
unknow_lost = max(0, eq - actual)  (book > actual 的差额)
```

### 2.2 21311147 洁柔纸巾 5/16 逐步追踪

```
5/15: init=245, sale=7, eq=238, actual=238 → end=238, unknow=0
5/16: init=238, sale=3, eq=235, actual=82 → end=82, unknow=153!

book inventory:  245(5/15 init) - 7(5/15 sale) = 238 → 5/16 init
actual inventory: 82 (system snapshot)
gap: 238 - 82 = 156 ... but eq=235, so unknow = 235-82 = 153

profit = sale(26.7) + end(656) - init(1,904)
       = 26.7 + 656 - 1,904 = -1,221
```

5/16 的系统快照显示实际库存只有 82 件，但账面有 235 件。差额 153 件变成 `unknow_lost`。

### 2.3 20101541 农夫山泉 5/16

```
init=196, sale=7, eq=189, actual=143 → end=143, unknow=45
profit = 76.3 + 1440 - 1974 = -457
```

### 2.4 不是"错误清零"

盘点机制本身正确：
- 每天都有系统快照（1,560-1,590 SKU），5/16 没有异常高的盘点量
- 系统快照提供了实际库存数据，差额正确反映为 unknow_lost
- 这不是标品被"错误日清"或"强制清零"

## 三、根因分析

### 3.1 账面库存为什么被高估？

洁柔纸巾 5/16 的账面库存 238 件来自前一天 end_stock=238。这个值又是从前一天 end_stock 传递过来... 追溯链：

```
5/6:  recv=180 → init=0, end=180
5/8:  recv=100 → init=180, end=280
5/9-15: 正常销售, end 从 280 递减到 238
5/16: actual=82, unknow=153
```

账面库存从 5/6 的 180 件开始积压，每天销售 3-7 件。但系统快照显示实际只有 82 件。这意味着**账面库存从一开始就可能被高估了**。

### 3.2 可能原因

1. **EUC=0 导致金额侧不准确** → 但不影响数量侧（qty 来自源表）
2. **init_stock_qty_src 偏大** → 首日 init 来自源表 `strategy_fm_purchase_di`，可能不可靠
3. **系统快照不完整** → `actual_stock_qty` 可能只覆盖部分库位
4. **真实损耗** → 虽然标品理论无损耗，但实际可能破损/过期/被盗

### 3.3 这是上游数据问题的症状

盘点机制揭露了账面与实际的不一致。这不是 stock.py 的 bug，而是上游数据（源表 init_stock、日常收货/销售记录）不完整或不准确。FIX-001（compose 推导）、FIX-002（EUC 兜底）、FIX-004（BOM 转移）会改善总利润，但不会直接修复数量侧的差异。

## 四、修复建议

| 方案 | 描述 | 优先级 |
|------|------|:---:|
| A: 接受差异 | 盘点机制正确，差异反映真实库存状况 | 🟡 |
| B: 降低盘点触发频率 | 只有 `created_by != '系统'` 才触发 is_counted | 🟡 |
| C: 增加差异阈值 | 只有差异 > 一定比例（如 20%）才触发 is_counted | 🟢 P2 |
| D: 排查源表 init | 首日 init_stock_qty_src 的准确性 | 🟢 P2 |

**当前建议：方案 A**。盘点差异是会计正确行为——发现了库存不一致就记录为损耗。如果掩盖这些差异（方案 B/C），会导致账面库存持续虚高，未来产生更大的集中核销。

## 五、影响评估

| 指标 | 5/16 影响 |
|------|:---:|
| 洁柔纸巾 | -1,221 |
| 农夫山泉 | -457 |
| 石湾玉冰烧 | -167 |
| 奔富葡萄酒 | -100 |
| 其他盘点差异 | ~-300 |
| **5/16 合计盘点相关亏损** | **~-2,200** |

5/16 FM 利润 = 1,044（全月最低之一），其中 ~2,200 来自盘点差异。去除后 5/16 利润 ≈ 3,244，属于正常范围。

这是**单日会计事件**，不是持续性 bug。
