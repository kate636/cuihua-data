# FIX-025：v0.16 分类来源与对比计算规则

## 问题

1. 包版本和运行 ID 仍标识 v0.14。
2. v0.15 熟食覆盖静态配置有 4 个 SKU，经营监控平台当前 `/overrides` 有 47 个。
3. 对比时用 v0.15 分类重写 v1.5 SKU 分类，实际分类差异只留在附加清单中。
4. 分类来源未完整确认时，大分类毛利差异仍被当成必须通过的检查。

## 核实计算规则

- v1.5 当前每日读取分类管理平台 `/api/sku-category/overrides`，该接口只返回熟食大类覆盖。
- 完整三级分类 `/api/sku-category/effective-mapping` 是预留接入点，当前 v1.5 未读取。
- 当前 `/overrides` 没有 `effective_from`，不支持仅凭最新响应重建历史快照。

## 修复

1. 包版本和新运行 ID 升级为 v0.16。
2. 运行清单增加分类规则来源、覆盖来源、校验和、依据状态和快照日期。
3. 静态历史规则可用于确定性诊断；未覆盖本次业务日时，`CATEGORY_SNAPSHOT_EVIDENCE` 阻止发布。
4. 对比库新增“各自实际分类”的日、周诊断表。
5. 原归一分类视图显式标记 `V016_OUTPUT_CATEGORY_NORMALIZED`。
6. 门店合计毛利继续执行±2% 对比检查；分类来源完整确认前，大分类差异只用于查问题。

## 保留接口

`t_v014_levels_result` 和 `v014_*` 物理表名继续使用，保持 125 字段和内部审计接口兼容。

## 待确认

分类平台规则的历史生效方式确认前，v0.16 不将当前 47 个 SKU 自动覆盖到 8 月 3—4 日。

## 验证结果

- 159 个单元与集成测试通过。
- 对比库新增各自实际分类的日、周诊断表，共识别 16 个在售 SKU日期记录分类标签差异。
- 门店合计保留毛利必须通过的检查，大分类行全部标记为诊断。
- 08-03～04 的全新重算在 D-1 准备日期遇到 SKU `20000158` 销售退回缺成本，因此停止。本次未用默认成本或 v1.5 结果补值。
- 对比程序使用本地固定保存的 08-03～04 试算结果；这不能证明重新完整运行的 v0.16 已通过发布验收。
- 服务器生产表写入为 0。
