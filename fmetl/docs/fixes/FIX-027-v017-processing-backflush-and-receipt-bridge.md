# FIX-027：v0.17 加工原料计算、换码和重复扣减修复

> 历史状态：本文只说明 v0.17 的改动。v0.18 已重新定义验收、剩余需求、BOM、成本和发布检查，
> 当前规则见 [DESIGN-009](../designs/DESIGN-009-v0.18-evidence-led-inventory-conversion-cost-profit.md)。

## 原来的问题

v0.16 只有在成品有盘点、原料账面余额足够时才计算加工。结果是：成品已经销售或报损，
系统仍可能不扣原料，也不给成品带入加工成本。

另外还有三类问题：

- 同一份原料可能同时被生熟联动报损和加工扣减；
- 验收数据已经把 A 记成 B 时，加工又可能重复扣一次 A；
- 少数同码验收只有金额、没有数量，导致门店日验收金额与 v1.5 不一致。

## 本次改了什么

1. 成品已经销售或普通报损，就根据配方反算原料用量；不再要求当天有成品盘点。
2. 原料账面余额不足不再让加工停算。原料照常扣减，超出库存的数量和成本单列，并从毛利中
   扣除。
3. 只有加工原料允许被扣到账面余额以下。BOM 拆分、固定换码和残余转移仍不能超出可用库存。
4. 生熟联动报损和加工只能选一条：同一配方原料当天符合生熟联动时，整个配方当天不再算
   加工。
5. 删除通过连续盘点推断包装换码的旧代码（`facts/pack_inference.py`）。
6. 固定换码改成两条清楚的路径：验收已经写成 B 时直接收 B；验收仍写成 A 时，只有唯一
   有效 A→B 关系才按 A 的当天验收量和固定比例转换。
7. 加工关系必须有正数比例和有效日期。单条关系有问题时只停这一条，不再让整张关系表失效。
8. 同码验收缺数量时，只有另一张验收表金额一致，才补数量；已有采购金额不改。
9. 同一商品集的验收码和销售码都被盘点时，只忽略验收码盘点，保留销售码盘点。
10. 同一 A→B 已经以 B 的正数验收量入账时，B 收货优先；加工关系保留供检查，但不再扣 A。

## 必须始终成立的规则

- 同一次加工中，全部原料转出金额之和必须等于成品转入金额；
- 商品在门店内部转换不会直接改变门店总毛利，只会改变成本落在哪个 SKU 或大分类；
- 原料库存不足产生的成本必须单列并扣回毛利，不得记作未知报损；
- 一笔收货金额只能记一次；补采购数量时不能改写已有采购金额；
- 商品重量可以计算重量换算参考比并检查正式比例，但不能证明当天发生了换码，也不能提供
  当天实际转换数量；
- v1.5 的结果不能进入 v0.17 的库存和成本计算。

## 2026-08-06～11 本地完整运行结果

数据范围：A3XV；2026-08-05 只用于准备 08-06 的期初库存；本地结果日期为 08-06～11。
数据来自本地复制的源数据缓存和经营平台当前加工关系，只读 v1.5 做对比；服务器写入 0。

| 检查项目 | 结果 |
|---|---:|
| 最终输出 | 88,996 行 |
| 可用加工关系 | 69 对，6 天合计 414 条关系×日期记录；没有缺失或非法比例 |
| 实际计算的加工 | 188 次 |
| 加工中原料转出金额 / 成品转入金额 | 6,519.06 / 6,519.06 元，两边相等 |
| 已经收成品 B，因此不再重复加工 | 6 个成品日，1 对关系，32 件，658.08 元 |
| 根据 A 的验收量直接换成 B | 46 次，10 对关系；A 转出 432.648，B 转入 692.061，金额 2,978.86 元 |
| 生熟联动报损优先 | 17 个成品日，涉及 12 个成品；这些日期不再算加工 |
| 多条配方含义不清 | 24 个成品日，涉及 4 个成品；未计入结果 |
| 原料和成品编码相同的无效加工关系 | 162 条关系×日期记录，27 对；忽略且不产生库存变化 |
| 必须通过的账目检查 | 10 项全部通过 |
| 商品每日销售额、销售量与 v1.5 | 完全一致 |

| 仍然缺成本 | 193 条商品×日期记录、52 个商品 |
| 分类 | 使用经营监控平台 2026-08-12 最新分类；1,449 个 SKU 直接匹配，11 个使用最新商品主数据 |
| 是否允许正式发布 | 不允许；原因是 193 条商品×日期记录仍无成本 |

“一次”指某门店、某一天、某一组来源商品和目标商品的一次计算，不等于 1 件商品。

## 对毛利的影响

同一时间段，旧 v0.16 的门店毛利为 28,392.74 元；最终 v0.17 为 25,611.95 元，减少
2,780.79 元。主要原因不是商品内部转换本身，而是 v0.17 不再把已经发生的加工消耗取消，
并且把原料库存不足产生的成本继续从毛利中扣除。

最终 v0.17 与 v1.5 的差异：

| 指标 | v0.17 比 v1.5 少 | 差异率 |
|---|---:|---:|
| 门店毛利 | 1,734.55 元 | 6.34% |
| 全链路毛利 | 1,706.35 元 | 4.91% |

新增固定换码后，门店毛利只比上一轮再减少 9.20 元。换码当天从 A 转出的 2,978.86 元与
转入 B 的 2,978.86 元完全相等；9.20 元来自换码后各 SKU 在后续日期的库存成本变化。

当前结果没有达到门店毛利差异不超过 2% 的目标；不得为接近 v1.5 删除真实换码、真实加工
成本或恢复重复计算。

具体日期、分类和 SKU 差异见 [v0.17 发布审核](../reviews/V0.17_RELEASE_REVIEW.md)。

## 如何确认修复没有引入新问题

- 已测试：无成品盘点、成品普通报损、原料库存不足、生熟联动优先、多配方、历史版本、关系
  有效期和同码无效关系；
- 已测试：同码验收金额一致时补数量，金额不一致时不补数量；
- 已测试：同一 A→B 已经收货时不再加工，同时不会误拦同一 A 流向其他 B；
- 已测试：BOM、固定换码等非加工转换仍不能超出可用库存；
- 最终本地结果的 10 项账目检查全部通过；
- 与 v1.5 对比时，销售和验收的精确核对全部通过。
