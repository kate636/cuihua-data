# DESIGN-007：v0.16 守恒驱动修正方法

## 1. 目标与样本

v0.16 先保证业务链路可解释、可守恒、可回放，再用 v1.5 定位口径差异。

- 门店：A3XV。
- 固定样本：2026-08-03、2026-08-04。
- v1.5：只读对照，不提供库存、成本和损耗补值。
- 边界：本地影子库，不写服务器业务表。

## 2. 改动准入

一项修改必须同时满足：

1. 在固定样本中可重复。
2. 能定位到源字段、关系证据、日账公式或聚合节点。
3. 违反业务定义、数量守恒、金额守恒、跨日连续或层级可加性。
4. 有自动化测试，修复结果不依赖 v1.5 趋同。

关系含义、生效日期、转换比例或盘点承接码不明确时，保留诊断，不修改正式过账。

## 3. 审核顺序

```text
外部事实
→ 关系命中与内部过账
→ SKU 日账数量、金额
→ D+1 期初继承
→ 单价链
→ SKU 到 SPU、大分类、门店聚合
→ v1.5 差异归因
```

下钻顺序：

```text
日期合计 → 日期×大分类 → 日期×SPU → 日期×SKU → 源记录
```

单价统一用对应数量作分母。期初、销售成本、已知损耗、内部转出、期末和未知损耗必须回到同一日账单位成本。

## 4. 分类处理

### 4.1 已核实现状

- v1.5 当前读取经营监控平台 `/api/sku-category/overrides`，用于熟食大类覆盖。
- 平台完整三级分类 `/api/sku-category/effective-mapping` 尚未接入 v1.5 ETL。
- v0.15 静态配置只有 4 个熟食覆盖 SKU，当前平台接口有 47 个。
- 平台当前接口未提供每条规则的 `effective_from`，无法仅凭当前响应重建历史分类快照。

### 4.2 v0.16 规则

1. 计算过程只读本次运行冻结的分类快照。
2. 运行清单记录分类来源、业务日、规则版本、行数和校验和。
3. 快照日期、SKU 唯一性或校验和不合格时，结果只用于诊断。
4. 历史生效规则未确认前，不用当前 47 个 SKU 覆盖历史日期。

### 4.3 对比口径

同时保留两种视图：

- **实际分类视图**：两个版本各用自己输出的分类，用于发现分类漂移。
- **v0.16 归一视图**：两边 SKU 按同一份 v0.16 快照重聚合，用于分解成本和关系差异。

分类快照未闭合前，大分类差异为诊断项。门店合计不受分类映射影响，继续作为硬门禁。

## 5. v0.16 确定修复

| 修复 | 根因 | 处理 |
|---|---|---|
| 版本身份 | 当前包版本和运行 ID 仍标识 v0.14 | 包版本、运行 ID 和新文档统一为 v0.16；保留 `t_v014_levels_result` 物理表名以维持接口兼容 |
| 分类证据 | 静态熟食名单已落后于平台 | 运行清单增加分类规则校验和与来源；证据不完整时阻止发布 |
| 分类对比 | 用 v0.15 分类重写 v1.5 后再比较，会遮蔽实际分类差异 | 分离实际分类和归一分类两种诊断，明确标注对比基准 |
| 大分类门禁 | 分类来源未闭合时，大分类差异被误当成账本错误 | 大分类暂作诊断，门店合计继续执行毛利硬门禁 |

## 6. 保留诊断

- 零成本出库继续阻止发布，不用 v1.5 成本补值。
- 熟食、烘焙加工缺产出证据时，不生成加工过账。
- 双码重复盘点、商品集缺转换证据、牛奶包装比例和蔬菜全转规则继续隔离。
- 猪肉、牛羊、加工和换码仅在正式关系、比例、生效日和当日证据闭合后过账。

## 7. 验收

- 全量单元测试通过。
- 销售、验收、已知损耗和人工盘点的外部事实保真。
- SKU 数量、金额和 D+1 连续性残差为 0。
- BOM、加工和换码内部过账金额残差为 0。
- 分类快照证据缺失时，不产生“可发布”结论。
- 对比库可分别查看实际分类差异和 v0.16 归一差异。
