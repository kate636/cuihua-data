# DESIGN-007：v0.16 前后总额相等驱动修正方法

## 1. 目标与样本

v0.16 先保证业务过程可解释、可前后总额相等、可回放，再用 v1.5 定位计算规则差异。

- 门店：A3XV。
- 固定样本：2026-08-03、2026-08-04。
- v1.5：只读对照，不提供库存、成本和损耗补值。
- 边界：本地试算库，不写服务器业务表。

## 2. 改动准入

一项修改必须同时满足：

1. 在固定样本中可重复。
2. 能定位到源字段、关系依据、每日库存和成本记录公式或聚合节点。
3. 违反业务定义、转换前后数量按比例一致、转出金额等于转入金额、跨日连续或层级可加性。
4. 有自动化测试，修复结果不依赖 v1.5 趋同。

关系含义、生效日期、转换比例或盘点承接码不明确时，保留诊断，不修改正式转换记录。

## 3. 审核顺序

```text
外部事实
→ 关系符合与内部转换记录
→ SKU每日库存和成本记录数量、金额
→ D+1 期初继承
→ 单价计算过程
→ SKU 到 SPU、大分类、门店聚合
→ v1.5 差异归因
```

查看明细顺序：

```text
日期合计 → 日期×大分类 → 日期×SPU → 日期×SKU → 源记录
```

单价统一用对应数量作分母。期初、销售成本、已知损耗、内部转出、期末和未知损耗必须回到同一每日库存和成本记录单位成本。

## 4. 分类处理

### 4.1 已核实现状

- v1.5 当前读取经营监控平台 `/api/sku-category/overrides`，用于熟食大类覆盖。
- 平台完整三级分类 `/api/sku-category/effective-mapping` 尚未接入 v1.5 ETL。
- v0.15 静态配置只有 4 个熟食覆盖 SKU，当前平台接口有 47 个。
- 平台当前接口未提供每条规则的 `effective_from`，无法仅凭当前响应重建历史带日期且不可修改的分类副本。

### 4.2 v0.16 规则

1. 计算过程只读取本次运行固定保存、带日期且不可修改的分类副本。
2. 运行清单记录分类来源、业务日、规则版本、行数和校验和。
3. 快照日期、SKU 唯一性或校验和不合格时，结果只用于诊断。
4. 历史生效规则未确认前，不用当前 47 个 SKU 覆盖历史日期。

### 4.3 对比计算规则

同时保留两种视图：

- **各版本原分类结果**：两个版本各用自己输出的分类，用于发现分类不同。
- **统一分类视图**：两边 SKU 都按同一份 v0.16 分类记录重新汇总，用于区分成本差异和商品关系差异。

带日期且不可修改的分类副本来源未完整确认前，大分类差异只用于查问题。门店合计不受分类映射影响，继续作为必须通过的检查。

## 5. v0.16 确定修复

| 修复 | 根因 | 处理 |
|---|---|---|
| 版本身份 | 当前包版本和运行 ID 仍标识 v0.14 | 包版本、运行 ID 和新文档统一为 v0.16；保留 `t_v014_levels_result` 物理表名以维持接口兼容 |
| 分类依据 | 静态熟食名单已落后于平台 | 运行清单增加分类规则校验和与来源；依据不完整时阻止发布 |
| 分类对比 | 用 v0.15 分类重写 v1.5 后再比较，会隐藏两版原始分类差异 | 同时提供“各自原始分类”和“双方统一使用 v0.16 分类”两种对比，并明确标注分类来源 |
| 大分类检查 | 分类来源未完整确认时，大分类差异被误当成每日库存和成本计算错误 | 大分类暂时只用于查问题，门店合计继续执行毛利检查 |

## 6. 保留诊断

- 零成本出库继续阻止发布，不用 v1.5 成本补值。
- 熟食、烘焙加工缺产出依据时，不生成原料转出、成品转入记录。
- 双码重复盘点、商品集缺转换依据、牛奶包装比例和蔬菜全转规则继续不计入正式计算。
- 猪肉、牛羊、加工和换码只有在关系已确认、比例有效、生效日明确且当天数量来源齐全时，才计入每日库存和成本。

## 7. 验收

- 全部单元测试通过。
- 销售、验收、已知损耗和人工盘点的外部事实保真。
- SKU 数量、金额和 D+1 连续性平衡差为 0。
- BOM、加工和换码内部转换记录金额平衡差为 0。
- 带日期且不可修改的分类副本依据缺失时，不产生“可发布”结论。
- 对比库可分别查看各版本原始分类差异，以及双方统一使用 v0.16 分类后的差异。
