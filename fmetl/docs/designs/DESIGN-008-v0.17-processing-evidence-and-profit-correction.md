# DESIGN-008：v0.17 加工证据、A进B出与毛利修正

## 1. 目标

v0.17 不以“更接近 v1.5”为最高优先级，而是先保证每条 A进B出都能回答四个问题：

1. A 和 B 的关系来自哪里；
2. 当天为什么确认发生了数量流；
3. 数量比例和金额比例来自哪里；
4. 同一数量是否可能被报损、验收或另一条内部关系重复扣减。

v1.5 只用于只读对比，不补 v0.17 的成本、库存、关系或盘点。

## 2. A进B出关系与比例的唯一来源

| 路径 | 关系证据 | 当日数量证据 | 数量比例 | 金额比例/成本 | 无比例时 |
|---|---|---|---|---|---|
| 同码验收 | `source_article_id = target_article_id` | `purchase_di`，必要时同码 `receive_sale` 桥接 | 1:1 | 采购金额原值 | 不存在缺比例分支 |
| 已分配跨码验收/换码 | `article_convert` 固定 A→B；少数上游已分配事实无该边时保留实事实审计 | `purchase_di` 已直接给出 B 数量和金额；`receive_sale` 可给 A 数量 | 优先 `article_convert.parent_rate`；否则用 A/B 实际数量比，商品重量比只作复核 | B 采购金额原值 | 不需要当日转换明细；B 直接作为外部验收入账，不能再造一次内部转换 |
| BOM 拆解 | 官方猪肉/牛肉 BOM 边 | `receive_sale` 父数量、子数量 | 公共数量按 `sale_recev_rate`，缺失时按子数量归一 | 优先 `spilit_sale_article_amt`，不完整时按 `sale_recev_rate`；父成本 100% 分完 | 无法建立数量或金额分配时整事件报错/隔离 |
| 加工 | 经营平台加工关系 API/带日期导出 | 成品净销售 + 成品普通已知报损 | `raw_qty / yield_qty` | 全部原料实际成本求和，100% 转入成品；没有独立折价率 | 比例为空、非有限或不大于 0 时拒绝入 stage |
| 商品集 | 同商品集 + 最新 `dim_goods.unit_weight` | 无独立数量事实 | 可得规格比例，但只作审计 | 无 | 若 `purchase_di` 有 B 数量/金额则走已分配跨码验收；否则不虚构当日流 |

`cost_rate = 1` 的含义是“内部事件价值守恒”，不是原料单价等于成品单价。成品单位成本为：

```text
成品转入金额 = 同一事件所有原料转出金额之和
成品转入单价 = 成品转入金额 / 成品转入数量
```

## 3. 加工反冲公式

对门店、日期、成品 `F`：

```text
普通报损_F = max(0, 已知报损_F - 生熟联动报损_F)
成品消耗量_F = max(0, 净销售量_F + 普通报损_F)

对每个原料 R：
原料消耗量_R = 成品消耗量_F × raw_qty_R / yield_qty_F
```

数量只证明已消费的成品，不声称重建当天总生产量或未售成品库存，因此不要求成品盘点。

## 4. 生熟联动优先且二选一

如果同一配方中的任一原料 SKU 当天存在生熟联动原料报损：

- 生熟联动报损保留在已知报损路径；
- 整个成品加工组当天不生成原料转出、成品转入；
- 不做“先占用一部分再加工剩余部分”的数量抵扣；
- `PROCESSING_RAW_LOSS_PRIORITY` 硬门禁保证同一原料日不能同时出现两条路径。

这是用户确认的业务优先级，代码不再维护复杂的部分占用状态。

## 5. 为什么取消原料余额门槛

加工量来自已经发生的成品销售/报损。原料账面余额不足只能说明原料期初、验收、BOM、盘点或成本证据不完整，不能把已经发生的成品消耗改成 0。

因此：

- `compose_out` 可以超过原料账面池；
- 超过部分进入日账 `negative_clamp`，期末数量钉 0；
- 透支数量按同一可审计单位成本计入 `neg_clamp_cost_amt`，毛利明确扣回；
- BOM、换码、残余转移和退货仍禁止超过库存池，不能借加工例外放宽。

## 6. 外部跨码验收优先于同一加工关系

`purchase_di` 有时已经把 A 码验收直接分配到 B 码，并给出实际入账的 B 数量和金额。
若同一门店、日期、A、B 又命中加工关系，再按 B 的销售/普通报损反冲 A，会重复记录同一
A→B 变化。

v0.17 只读取已经通过验收规范化并实际进入外部库存池的跨码流水作为优先证据：

- 同一 `store + day + A + B` 有正的外部验收数量时，保留正式加工关系用于审计，但整组加工不过账；
- 仅有金额、无数量并已被验收模块隔离的行不能抑制加工；
- 只按 A 码相同、但 B 码不同的外部验收不能误拦另一条加工；
- `PROCESSING_EXTERNAL_RECEIPT_PRIORITY` 硬门保证同一 A→B 不同时存在外部验收和加工转出。

这里没有“当日换码转换明细表”。`article_convert` 是固定关系/比例，`purchase_di` 是当天数量和金额：二者命中时直接把 B 作为外部验收入账。若 `purchase_di` 已经给出 B 金额，再生成 A OUT/B IN 会把同一验收成本记两次，因此明确禁止。

“有关系可以直接转换”不等于“把 A 当日全部验收都转换”。本窗口唯一满足一对一固定关系且 A 有同码验收的 `21146343 → 21285264`，A 每天仍有销售并在 v1.5 保留期末库存，而 B 无销售/库存记录。若把 A 全部验收转换，六天会凭空形成约 32 组 B 库存并使 A 透支。因此关系可以替代不存在的明细表来确认方向和比例，但当日转换量仍以 `purchase_di` 已明确分到 B 的数量为准。

这是二选一优先级，不做“先扣外部验收数量、再加工剩余消费量”的部分抵扣。

## 7. 多原料与多配方的边界

同一个 `relation_id` 下有多条原料边时，视为一个共同配方：所有原料成本相加后一次性转入成品。

同一个成品同日出现多个 `relation_id` 时，现有 API 无法说明它们是：

- 多原料共同配方；
- 可替代原料方案；
- 历史版本重叠；
- 多选一半成品组合。

因此 v0.17 以 `MULTIPLE_ACTIVE_PROCESSING_RECIPES` 整组成品隔离。不同日期不重叠的历史版本允许存在；同一原料→成品在同一天重叠多个版本直接拒绝构建 stage。缺生效日期、未批准或不在有效期的脏关系逐行隔离，不能把同一导出中其他日期完整的关系一起停算。

## 8. 同码验收数量桥接

`purchase_di` 偶尔存在“同销售码采购金额已分配、数量为空/0”，而 `receive_sale` 保存了同一门店、日期、源代码、销售码的实际验收数量。只在以下条件同时满足时补数量：

1. 源码等于销售码；
2. 采购数量为空或 0；
3. `receive_sale` 数量非 0；
4. 采购金额为空，或两表金额差不超过 0.01。

若采购金额已存在，只补数量并保留采购金额；金额不一致仍进入 `DIRECT_RECEIPT_AMOUNT_WITHOUT_QUANTITY`，不猜数量。

## 9. 盘点规则

- 只有明确操作人证据的盘点覆盖期末；
- 系统快照只审计；
- 同商品组同时出现验收码和销售码盘点时，只忽略验收码盘点，保留销售码盘点；
- 盘点不参与加工消耗量推导。

## 10. 发布与验收条件

硬门禁：负期末数量/金额、SKU 数量/金额平衡、外部事实守恒、D+1 滚动、内部金额守恒、生熟联动优先、外部跨码验收优先、BOM 父品完全转移共 10 项。

发布门禁另外要求：

- 所有销售、报损和内部转出有正成本证据；
- 分类快照不可变且覆盖完整运行窗口；
- 只读对比中 SKU 销售和门店日验收金额完全一致；
- 门店毛利超出 2% 时必须下钻解释，不能为了过线删除真实成本。

## 11. 仍需业务判断与已确认边界

仍需业务判断：

1. 4 个多关系 ID 成品的配方组合语义；
2. 缺当日成本时，是否允许历史成本回退，以及最大有效天数。

已经确认、代码不再等待判断：

- 系统库存快照不能代表正式实盘，只保留审计；
- 分类统一使用经营监控平台最新日期快照，并对 08-06～11 整窗映射；11 个未命中 SKU 回退同次运行最新 `dim_goods`。

在这些问题明确前，v0.17 保留诊断产物但不标记为可发布。
