# DESIGN-005：fmetl v0.14 商品集关系重构迭代计划

> 状态：本地七日影子版已实现，待业务关系确认和生产发布审批  
> 范围：A3XV；不修改现有 v1.5 生产链路  
> 已验证窗口：2026-07-17 至 2026-07-23；自动窗口仍要求全部必需源共同连续完整 7 天  
> 目标：以商品集 ID 连接订购、验收和销售角色；加工关系及猪牛 BOM 独立处理；独立计算并覆盖 v1.5 已有输出指标、维度和聚合层级

## 1. 结论

可以按以下主线建设 v0.14：

```text
商品集 ID：连接大多数订购码、验收码、销售码
    +
加工关系：原料 → 成品，按关系和成品消耗反推原料转出
    +
猪肉 / 牛肉 BOM：父品 → 多个子品，复用 v0.11 的拆分和成本守恒方法
    +
例外清单：个别蔬菜、饮料包装及关系或比例不明的 SKU
    ↓
统一 SKU 日库存、成本和毛利账本
    ↓
按 v1.5 的指标、维度和聚合合同输出 123 个兼容字段，并追加商品集 ID 和名称
```

但需要明确一个边界：**商品集 ID 只能证明多个 SKU 属于同一商品集，不能单独证明当天发生了转换，也不提供转换数量和比例。** 正式过账仍必须有当日验收／销售品分配事实，或有已确认的固定转换规则。缺少数量或比例时进入例外清单，不自动兜底。

因此，v0.14 不是把 SKU 直接合并成商品集库存，而是用商品集 ID 缩小关系范围，再按实际关系对完成 SKU 间转入、转出。SKU 库存和成本仍分别核算。

**v0.14 不参考 v1.5 的关系判定、库存、成本和毛利计算链路，也不读取 v1.5 派生结果回填。** v1.5 只用于确认需要输出哪些指标、维度和层级，以及这些结果如何聚合；损耗和毛利的特殊展示调整可以单独参考，但必须与 v0.14 的会计底项分列保存。

版本职责固定如下：

- **v0.13：技术主干。** 沿用源合同、关系分型、统一日账、异常隔离、运行快照和自动校验框架，在其上补齐遗漏能力并形成 v0.14。
- **v0.11：业务能力迁移清单。** 只提取已验证的猪牛 BOM、单位归一、金额守恒、跨日滚动、完整执行与发布能力；不复制旧模块，也不以其计算结果回填。
- **v1.5：输出合同。** 只确认指标、维度、聚合方式及必要的损耗／毛利特殊展示规则，不作为关系、库存、成本或毛利计算基准。
- **Hive 镜像事实与已确认业务规则：计算真值。** 销售、验收、订单、盘点、报损、SCM、BOM、商品与价格均读取《`strategy_fm v1.5 字段与表结构手册`》所列 Hive→StarRocks 镜像字段；采购确认的加工关系仍来自经营平台。`v014_stage_*` 由程序从这些来源生成，不是外部数据源。
- **关系辅助证据不等于业务事实。** 商品集和当日换码明细只辅助识别关系或证明转换事件；库存、成本、损耗和毛利的正式底项仍只来自 Hive 镜像事实与获批关系过账。

### 1.1 正式数据边界

- `v014_mirror_*`：按字段手册从 Hive 镜像抽取的本地只读缓存。
- `v014_mirror_source_manifest`：逐源保存 StarRocks 镜像表、字段手册中的 Hive 原表、分区、行数、校验和与证据类型；没有 Hive 血缘的商品集/换码明细只能标为辅助关系证据。
- `v014_stage_*`：ETL 程序由镜像自动生成的内部标准层，不是人工表、不是外部输入接口。
- `strategy_fm_chdj_article_di` 的库存、成本、损耗和毛利列不进入 v0.14 账本；日清正式输入优先使用 `strategy_fm_dim_day_clear`。
- 影子窗口读取 `D-1 + 7 个发布日`；`purchase_di.init_stock_*` 只允许作 D-1
  bootstrap 种子并标记来源。先完整计算 D-1 期末，再作为首个发布日期初；此后均由
  v0.14 期末精确滚动，禁止每日重读上游期初期末。

## 2. 判断依据

### 2.1 商品集方案已验证可用

指定对话中的 2026-07-27 隔离测试结果：

- v1.5 的 3,083 个 SKU 映射为 2,905 个商品集；3,064 个 SKU 有映射，19 个 SKU 暂以自身编码兜底。
- 原 v1.5 六个分析层级、金额、销量、销售重量、损耗金额／数量和渠道指标均保持守恒。
- 在原六层 5,616 行不变的基础上，新增 3,498 行“商品集”层，结果共 9,114 行。
- v1.5 result 原有 123 个字段全部保留；测试版只追加 `article_group_id`、`article_group_name` 两列。

这只证明商品集 ID 可用于关系识别和新增分析层，不代表 v0.14 应复用 v1.5 的计算过程。

### 2.2 未覆盖关系高度集中

2026-07-21、仅统计带“可订”或“可售”标签的 SKU：

- 2,274 个验收 SKU 中，1,917 个同时存在订购和销售关系；1,825 个完整链路落在同一商品集，链路覆盖率为 95.2%。
- 按具体跨码关系对统计，共 872 对；258 对同商品集，614 对跨商品集。
- 614 对未覆盖关系只涉及 107 个验收 SKU，主要集中在：

| 关系范围 | 未覆盖关系对 | 验收 SKU | v0.14 处理 |
|---|---:|---:|---|
| 猪肉 | 524 | 33 | 猪肉 BOM |
| 烘焙及预制菜加工 | 62 | 62 | 加工关系 |
| 牛肉 | 18 | 2 | 牛肉 BOM |
| 蔬菜 | 4 | 4 | 确认后按固定换码或例外隔离 |
| 饮料包装 | 6 | 6 | 补充固定包装比例或例外隔离 |

按关系对计算时，猪肉一父多子会产生大量边，因此“关系对覆盖率”低于“完整链路覆盖率”。从关系集中度看，“商品集主干 + 加工 + 猪牛 BOM + 少量例外”的架构成立。

### 2.3 当前仍有两个实施前置条件

1. `article_group_id_Key` 在 A3XV 没有明确区域分区。2026-07-27 测试使用 `area_name IS NULL` 的通用映射；正式实施前必须由商品／业务负责人确认其权威性。
2. 商品集表是商品关系快照，不是订购、验收或转换流水。完整的“订购 → 验收”事实源仍需确认；在此之前不能把商品集映射冒充实际订验数量。

## 3. v0.14 处理范围

本版采用“v0.13 技术主干 + 补齐业务能力”的迁移方式，不回到 v0.11 继续扩建，也不按 v1.5 的处理逻辑重做计算。

### 3.1 纳入本版

- 销售、验收、SCM、损耗、盘点、促销、让利、订单和商品主数据等原始业务事实；不读取 v1.5 派生库存、成本、损耗或毛利结果。
- `article_group_id_Key` 商品集映射快照。
- 采购确认并按生效日期维护的加工关系及比例。
- 猪肉、牛肉正式 BOM、拆分比例、成本比例和单位换算。
- 商品集覆盖的订购码、验收码和销售码关系。
- v0.14 独立计算的关系、数量、成本、库存和毛利底项。
- v1.5 已有指标、维度和聚合层级的完整输出合同；特殊损耗和毛利只参考展示调整规则。

### 3.2 不在本版自动推断

- 仅凭同商品集 ID 生成当天转换数量。
- 仅凭同 SPU、同物料码、名称相似或同时可售生成转换。
- 无比例的跨码关系。
- 未确认是否 100% 转换的蔬菜、包装商品。
- 门店补录加工量；加工正式量改由 ETL 计算，源加工录入仅作影子对照。

## 4. 目标数据链路

```text
原始业务事实表 + 商品集快照 + 加工关系快照
                    ↓
1. 来源标准化
   销售、验收、盘点、报损、订货、渠道、商品角色分别保留
                    ↓
2. 关系解析
   同码 / 商品集关系 / 加工 / 猪牛 BOM / 例外隔离
                    ↓
3. 当日数量计划
   外部进货只记一次；内部转出与转入成对生成
                    ↓
4. SKU 日账本
   期初 + 外部进货 + 内部转入 - 销售 - 损耗 - 内部转出 = 期末
                    ↓
5. 成本与毛利
   当日加权成本；内部金额守恒；D+1 期初精确复制 D 日期末
                    ↓
6. 指标、维度与聚合输出
   flag_sku / cust / levels_sum / levels_result + 关系审计表
```

## 5. 关系判定与过账规则

### 5.1 判定优先级

同一个“门店 + 日期 + 来源 SKU + 目标 SKU”只允许一种正式过账方式：

1. **同码**：验收码等于销售码，直接进入该 SKU 的外部进货。
2. **猪牛 BOM**：命中正式猪肉／牛肉 BOM，按父子关系拆分。
3. **加工**：命中采购确认且当日有效的加工关系，按成品消耗反推原料。
4. **商品集转换**：两端属于同一商品集，且有当日关系事实和可靠比例。
5. **例外隔离**：关系类型、方向、比例或当日数量任一缺失，不进入正式库存和成本池。

BOM 和加工优先于商品集。商品集用于确认身份范围，不能覆盖更具体的业务关系。

### 5.2 商品集关系

商品集关系解决“哪些码属于同一商品”，不直接合并库存：

- 订购码 → 验收码：商品集 ID 用于校验关系；数量取实际订验事实，单位按明确比例归一。
- 验收码 → 销售码：优先使用 `purchase_di`／验收销售分配中的当日目标 SKU、数量和金额。
- 同一商品集存在多个可售 SKU 时，必须以当日分配事实选目标；没有事实时不得按最小编码或任意规则选择。
- 比例优先级：当日事实比例 > `article_convert` 精确比例 > 已确认的固定规格比例。三者都没有则隔离。
- 商品集映射按业务日取快照，禁止用今天的关系改写历史。

### 5.3 猪肉、牛肉 BOM

复用 v0.11 已验证的方法，但只复用业务规则和守恒约束，不复制旧模块：

1. 父品外部验收按“门店 + 日期 + 父品 + 验收单”去重，只入池一次。
2. 父品数量保留父品单位，子品数量保留子品单位；通过 `article_convert` 归一到公共重量做校验。
3. 数量按出成率拆分，成本按成本比例分配；共享子品按共享组规则分摊。
4. 父品转出金额合计等于全部子品转入金额合计，单事件允许误差不超过 0.01 元。
5. 父品全部转出后不再保留独立毛利；环、缺比例、比例冲突或单位不完整整组隔离。
6. 猪肉、牛肉之外的 BOM 不在本版自动扩面，先进入观察表。

### 5.4 加工关系

门店不再填加工量，只保留盘点和实际报损；采购只维护一次关系、比例和生效日期。

对纯加工成品：

```text
成品当日产出量
= 期末库存量 - 期初库存量
  + 净销售量 + 已知报损量
  - 其他外部流入量 + 其他内部转出量

原料 i 转出量
= 成品当日产出量 × raw_qty_i / yield_qty
```

完整实现以 SKU 库存方程为准，不能只使用“销售 + 报损”。若盘点缺失、关系未生效、比例冲突、原料不足或成品同时存在外部进货，进入隔离或影子估算，不进入正式账。

`strategy_fm_compose_di` 只作源过程记录和影子对照，不再作为门店必须填写的正式数量源。

### 5.5 例外处理

首批例外包括：4 个蔬菜验收 SKU、6 个饮料包装 SKU，以及关系或比例不完整的其他商品。

例外表至少输出：

```text
store_id, business_date
source_article_id, target_article_id
article_group_id
candidate_relation_type
quantity_evidence, ratio_evidence
quarantine_reason
first_seen_date, last_seen_date
```

例外不得静默回退为同码进货，也不得把差额直接塞入未知损耗。

## 6. 库存、成本与毛利

### 6.1 SKU 日库存方程

```text
available_qty
= init_qty + receive_qty + internal_in_qty + sale_return_qty + inventory_gain_qty

end_qty
= available_qty - gross_sale_qty - known_lost_qty - internal_out_qty - inventory_decrease_qty
```

- 有可靠盘点证据的非负实盘数量覆盖计算期末，差额记未知损耗或盘盈；盘点金额按当日单位成本重算。
- 无有效人工盘点时按库存方程计算期末；`day_clear` 仅作标签，普通系统库存快照仅作审计。
- 计算结果不得保留负库存；透支数量和金额单列，不允许带到次日期初。
- D+1 期初数量和金额必须精确复制 D 日期末，不按单位成本反算。

### 6.2 成本

```text
issue_unit_cost = 可用库存金额 / 可用库存数量
```

- 销售、已知损耗、BOM／加工／商品集内部转出均使用当日同一单位成本。
- 内部转出金额必须等于对应转入金额，换码、拆分和加工不能凭空产生毛利。
- 商品集 ID 不能把不同 SKU 的期初库存和成本直接汇成一个池；只有正式内部事件才能转移成本。

### 6.3 毛利

延续 v0.13 的单次定价原则：销售、外部进货、内部转入／转出和期初期末只在 SKU 日账本计算一次；报告层只聚合，不重新定价。

## 7. 输出指标、维度与聚合合同

本节只参考 v1.5 的**输出结构**，不参考其数据处理过程：

- 参考字段：需要输出哪些底项、比率和运营指标；
- 参考维度：门店、日期、日清、大／中／小分类、SPU、SKU；
- 参考聚合：各层级的 SUM、AVG、去重计数、排名、占比及比率分子／分母；
- 允许参考：特殊损耗和毛利的展示调整；
- 禁止参考：v1.5 的关系判定、库存结果、成本结果、损耗结果或毛利结果作为 v0.14 输入。

### 7.1 输出表

v0.14 对外只物理生成一张输出表，不覆盖也不依赖 v1.5：

```text
t_v014_levels_result
```

并新增关系与过程审计表：

```text
v014_relation_registry
v014_relation_resolution
v014_internal_posting
v014_sku_daily
v014_quarantine
v014_run_manifest
v014_validation_result
```

### 7.2 字段合同

- `t_v014_levels_result` 必须覆盖 v1.5 result 的 **123 个输出字段**，字段名、顺序、类型、注释和业务含义均不得减少或改名；字段值必须由 v0.14 底项独立计算。
- 在 123 个既有输出字段之后追加 `article_group_id`、`article_group_name`；若保留商品集分析层，则 `level_description='商品集'`。
- 原六层“门店／大分类／中分类／小分类／SPU／SKU”全部保留；商品集是新增平行层，不替换 SKU 或 SPU。
- `flag_sku`、`cust`和 `levels_sum` 的底项仅作为 `t_v014_levels_result` 内部计算过程，本轮不物理发布独立表。
- 新 ETL 暂时无法独立计算的字段必须先补齐来源、公式和聚合方式；禁止保留空列冒充完成，也禁止借用 v1.5 结果回填。

字段按以下五组逐项建立血缘：

1. 基础维度与层级；
2. 销售、渠道、客数和新老客；
3. 采购、SCM、促销和让利；
4. 库存、损耗、成本和毛利；
5. 售罄、动销、品效、周转、排名和占比。

## 8. 近一周测试方案

### 8.1 测试数据

首轮实际验证为 A3XV、2026-07-17 至 2026-07-23：

- 测试开始前检查全部必需源的分区完整性。
- 任一必需源缺一天，整个窗口回退到最近连续完整的 7 个业务日，不允许不同表拼接不同日期。
- 商品集、BOM、单位换算、可订可售和加工关系全部按业务日保存快照及 checksum。
- 测试只写本地 DuckDB 或独立 `_v014_test` 表，不修改 v1.5 表、任务、脚本和发布链接。

### 8.2 样本覆盖

除全量 7 日数据外，必须单列以下案例：

- 同码普通商品；
- 商品集内订购码、验收码、销售码不同的商品；
- 猪肉一父多子；
- 牛肉 BOM；
- 烘焙和熟食加工；
- 西红柿等蔬菜换码；
- 饮料／乳品包装单位换算；
- 盘点小数点错误、双码重复盘点、供应商多送和负库存保护。

### 8.3 自动校验

| 校验项 | 通过标准 |
|---|---|
| 源分区 | 7 天全部必需源齐全；checksum 可复现 |
| Schema | `t_v014_levels_result` 的 123 个原字段名称、顺序和类型一致，并追加 2 个商品集字段 |
| 粒度 | `store_id + business_date + article_id + day_clear` 等业务键无重复 |
| 关系 | 每个实际来源→目标事件只有一种正式类型；其余全部进入例外表 |
| 商品集 | 映射在同一业务日唯一；无映射、跨区域冲突全部显式列出 |
| BOM | 父品只入池一次；父转出与子转入金额差每事件 ≤ 0.01 元 |
| 加工 | 原料转出与成品转入金额守恒；关系和比例均按生效日读取 |
| 库存 | 库存方程残差为 0；正式期末负库存为 0 |
| 跨日 | D+1 期初数量／金额等于 D 日期末，断点为 0 |
| 销售与渠道 | 销售金额、数量、重量、线上线下／接龙／及时达与原始订单事实对平 |
| 客数 | 总客数、渠道客数、新老客由原始订单键独立计算并完成去重校验 |
| 损耗与毛利 | 会计底项满足库存方程和金额守恒；特殊展示调整单列。与 v1.5 的差异只作诊断，不作为计算输入或硬性趋同目标 |
| 例外 | 未确认关系不进入正式成本池，不以未知损耗静默兜底 |

本地验证已通过 8 项硬门禁：外部观察量守恒、SKU 数量守恒、SKU 金额守恒、
内部过账金额守恒、BOM 父品全部转出、D+1 精确滚动、无负期末数量、无负期末金额。
当前 v1.5 参考对比中，销售事实和门店日验收金额完全一致，发生销售的 SKU
大分类映射完全一致；门店周毛利差异 -0.14%，全链路周毛利差异 -0.11%。
库存、成本、损耗、SKU 毛利及关系修正差异保留为诊断，不读取 v1.5 结果回填。
冻结的 123 个参考字段全部进入对比矩阵；v1.5 查询接口未返回的字段必须显式标记
`REFERENCE_UNAVAILABLE`，不能把缺失参考值当作 0。
