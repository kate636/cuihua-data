## 5. 当日单位成本

```text
可定价数量 = 期初数量 + 当日净验收 + 内部转入 + 销售退货
可定价金额 = 期初金额 + 当日净验收金额 + 内部转入金额 + 销售退货金额
```

BOM 父品当日拆分金额来自本次 `receive_sale` 验收金额，先从上述池中扣除。其余可用数量和金额
同号且数量非零时：

```text
当日单位成本 = 剩余可定价金额 ÷ 剩余可定价数量
```

该公式不能得到正成本时，只使用当日 `inventory_pool` 参考价。没有跨日单位成本回退。

销售、普通报损、加工转出、固定换码转出、商品集换码转出和其他非 BOM 转出都按当日单位成本
定价。销售退货使用当日成本；当日也无成本时保留问题并阻止发布。

当前有一个明确例外：熟食联动只把原料账本成本转到熟食大分类，不分配到具体熟食成品 SKU。
因此，被唯一熟食联动数量覆盖的 16 个成品日允许 SKU 单位成本为 0；对应成本只在熟食大分类
和门店层完整，单个成品 SKU 毛利不完整。是否进一步分配到具体成品 SKU 尚待业务决定。

## 6. BOM

1. 方向只取正式 BOM。
2. 父品实际验收数量和金额只取 `receive_sale`。
3. `receive_sale` 的父品→父品行表示本次验收仍留在父品的数量和金额。
4. 本次转出父品数量 = 父品验收数量 - 留在父品的数量。
5. 子品数量直接使用 `receive_sale.sale_article_qty`。BOM 权重不覆盖、不否定实际子品数量。
6. 子品金额优先使用完整且合计等于转出父品金额的 `spilit_sale_article_amt`；否则按正式 BOM
   权重归一化分配。
7. 父品历史期初库存不强制转空。本次只转换有完整当日数量证据的验收部分。
8. 父品金额、子品金额、子品清单或 BOM 单位换算不完整时，整组不生成事件并阻止发布。

父品和子品可能使用不同计量单位。系统使用 `article_convert ctype=1` 的 `sub_rate`
将子品实际数量折回父品单位：

```text
子品折回父品数量 = Σ(receive_sale.sale_article_qty × sub_rate)
```

该合计与父品本次转出数量的差绝对值必须不大于 0.002。超限、缺少 `ctype=1`
比例或 `sub_rate` 冲突时，整组停止。本周 97 组最大残差为 0.00102595，0 组超限。
`ctype=1` 只提供 BOM 单位换算，不另外生成换码事件。

8 月 5～11 日共有 8,491 条正式 BOM 关系日：614 条子品关系有当日验收事件，
7,877 条只保留正式方向。无当日 `receive_sale` 事件的关系不改库存。

## 7. 加工、固定换码和商品集换码

三类关系使用同一套成品剩余需求计算：

```text
成品需求 = 正向销售 + 普通报损 + 该成品作为下游原料的需求
已有成品 = 成品期初 + 成品直接验收 + 销售退货 + 已确认内部流入
本次转换产出 = max(成品需求 - 已有成品, 0)
来源商品用量 = 本次转换产出 × source_qty_per_target_qty
```

- 加工比例：`raw_qty ÷ yield_qty`。
- 固定换码比例：`1 ÷ parent_rate`。
- 商品集比例：`B 商品重量 ÷ A 商品重量`；按千克销售的商品重量按 1 千克处理。
- 同时保存 `source_qty_per_target_qty` 和 `target_qty_per_source_qty`，两者乘积必须等于 1。
- A 当天没有验收时可以使用期初库存。
- A 库存不足不取消加工或换码；仍记录转换，短缺数量进入透支成本。
- B 当天直接验收只减少需要转换的数量，不把当天全部加工置零。
- 盘点不参与加工量计算。

关系配置的每一种原料边都必须存在于加工关系接口。配置有两种原料、接口只返回一种时，整组
标记 `RECIPE_GROUP_INCOMPLETE`，不按单原料过账。完全相同的重复关系合并一条；比例或配方组
冲突时整对关系隔离并阻止发布。

账本字段保持业务含义：加工写 `compose_in/out`；固定换码和商品集换码写 `pack_in/out`。

## 8. 熟食联动和炒菜机报损

### 8.1 数量进入账本

通用报损没有原因和记录号，不能逐条证明是否已经包含熟食联动或炒菜机报损。因此采用已声明的
数量覆盖假设：

```text
特殊报损合计 = 熟食联动数量 + 炒菜机数量
有效已知报损 = max(通用报损数量, 特殊报损合计)
```

系统不把两张表的全部数量直接相加。审计表固定标记 `OVERLAP_ASSUMPTION_UNPROVEN`，表示无法
从源记录逐笔证明重合关系。

面向人的说明使用“熟食联动”。源表仍使用原值 `reason='生熟联动'`，代码和审计状态保留缩写
`SSLS`，避免改变已有数据接口。

### 8.2 熟食联动优先

- 熟食联动和加工二选一，熟食联动优先。
- 加法配方任一原料命中熟食联动时，整组加工不执行。
- 替代配方只有一套被同日熟食联动数量完整覆盖时，选择该配方；零套或多套同时满足时阻止发布。
- 本次熟食小龙虾 8 月 8、9 日只有蒜蓉原料 `20856762` 有熟食联动数量，因此选择蒜蓉配方；
  麻辣原料 `20038175` 没有同日熟食联动数量。

```text
熟食联动转移成本 = 熟食联动数量 × 原料当日单位成本
```

原料分类加回该金额，熟食类扣减同额。门店总毛利不变，分类间转出和转入合计必须为 0。

### 8.3 炒菜机展示规则

炒菜机报损先进入原料已知报损并扣减库存成本，再把同一账本成本全额加回公开毛利。它是展示
规则，不是库存成本守恒规则。没有先在账本扣减的数量不能加回。

## 9. 日清、盘点和透支

```text
理论期末 = 期初 + 验收 + 销售退货 + 内部流入 - 内部流出 - 正向销售 - 已知报损
```

处理顺序：

1. 有效人工盘点：期末等于人工盘点数量，差额进入未知损耗或盘盈。
2. 日清商品：当天净新增为正时清零；当天消耗超过新增时先消耗期初；超过期初的部分记透支。
3. 非日清理论期末小于 0：期末数量和金额设为 0，负差额保留在账目平衡字段，同时计算透支成本。
4. 其他：理论期末直接成为期末。

```text
透支成本 = max(-理论期末数量, 0) × 当日单位成本
```

门店毛利必须扣除透支成本，防止库存已用完但销售成本消失。系统库存快照不作为正式盘点。

同一关系 A、B 同日都有人工盘点时如何判定“矛盾”，尚待业务定义。本周有 1 条：2026-08-08
加工关系 `20101541 → 21087042`，A 实盘 9，B 实盘 29。当前保留两端盘点，不把“同时盘点”
直接判为矛盾，也不声称两端数量方程已经得到业务确认。

## 10. 毛利、供应链和客数

```text
门店毛利 = 销售额 - 验收金额
         - BOM转入 + BOM转出
         - 换码转入 + 换码转出
         - 加工转入 + 加工转出
         - 其他内部转入 + 其他内部转出
         + 期末库存金额 - 期初库存金额
         - 透支成本
```

已知报损已经通过期末库存减少反映成本，不再单独重复扣一次。

供应链公开毛利保持 v1.5 正向出库口径：

```text
公开供应链毛利 = 正向出库未税结算额 - 正向出库未税成本
```

另行审计含退仓口径。本次正向口径 7,468.7377 元，含退仓口径 7,369.0209 元，差
-99.7167 元。公开结果暂不改为净口径。

客数按有效订单去重：

- 订单状态只保留 `os.completed` 和 `os.split`。
- `first_buy_flag=true` 计新客。
- `first_buy_flag=false` 且有会员身份计老客。
- `first_buy_flag` 为空时既不计新客也不计老客。
- `jielong_flag=shop` 或明确真值计接龙。
- 19 点前统一按 `pay_at < 19:00:00`。
- 首购和线上/线下渠道先在整单层检查；同一订单不同 SKU 的这两类状态冲突时运行失败。
- 接龙按整单取值：订单任一 SKU 行为接龙真值，则整单计接龙。
