## 三、核心发现

### 发现 1：分摊逻辑是"按出肉率分配数量，单价保持 parent 均价"

```
BOM 分摊公式：
  sub_sale_article_qty      = parent_inbound_qty × dressing_rate
  sub_sale_article_purchase_amt = sub_sale_article_qty × parent_avg_inbound_price

结论：
  sub_unit_cost = sub_sale_article_purchase_amt / sub_sale_article_qty
                = parent_avg_inbound_price（单价不变）
```

**验证**：
- 黑猪 parent 均价 = 21.41，所有 sub 单位成本 ≈ 21.41
- 大白猪 parent 均价 = 14.84，所有 sub 单位成本 ≈ 14.84

### 发现 2：出肉率归一化验证

对于黑猪（parent=20045463）：
```
总拆出量 = 9.85 kg

假设 parent 进货量约 10 kg（推测）
出肉率合计 ≈ 98.5%（接近 100%）
```

### 发现 3：每个 parent 下所有 sub 使用相同的单位成本

这意味着：
- **不需要 cost_rate 反推**（分摊逻辑已内置）
- **分摊金额 = 分摊数量 × parent 均价**

## 六、结论

### purchase_di 表的 BOM 数据特点

1. **包含完整的 BOM 分摊数据**
   - parent 编码：`article_id`
   - sub 编码：`sale_article_id`
   - 分摊数量：`sale_article_qty`
   - 分摊金额：`sale_article_purchase_amt`

2. **分摊逻辑简单清晰**
   - `sub_unit_cost = parent_avg_inbound_price`（单价不变）
   - 按出肉率分配数量

3. **可用于直接计算**
   - 无需额外 BOM 边表
   - 无需 cost_rate 反推
   - 直接取 `sale_article_purchase_amt / sale_article_qty`

4. **问题：期末库存缺失**
   - 需要补充期末库存来源

## 七、建议的 BOM 处理方式

基于以上分析，BOM 商品的单位成本计算可以简化为：

```sql
-- 直接从 purchase_di 计算
SELECT
    sale_article_id,
    sale_article_purchase_amt / sale_article_qty AS unit_cost
FROM strategy_fm_purchase_di
WHERE article_id != sale_article_id  -- 只取 BOM 商品
```

**无需复杂的 BOM 边查询和 cost_rate 反推！**
